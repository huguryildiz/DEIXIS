# DEIXIS Design Guide

Rules for the web UI in `apps/web/src`. Checked against the code on 2026-10-16.

## 1. What the UI is for

Researchers search, screen, read and cite literature here. They read for a long time and check where each piece of evidence came from. The UI is a quiet research desk, not a dashboard or a chat app: light first, with a full dark theme.

- The deliverable (answer, report, table) comes first. Runs, steps and usage sit one level deeper.
- Every state is shown, including failure, uncertainty and "not checked".
- A visual state comes from a stored backend state. Copy never claims more than was checked: "located" is not "verified".
- Found, screened, included, inspected, given to the model and cited stay separate counts. Never merge them into one number.

## 2. The app is the reference

There is no separate mockup any more (D79). The shipped screens are the reference: Elicit's layout and density, with DEIXIS ink blue instead of teal.

- Example data never ships: titles, counts and names come from real records.
- A new feature goes into the nearest existing container and takes its look, rather than a new pattern.
- If existing copy would be false for a new feature, change the words, keep the layout.

## 3. Tokens

Defined once in `index.css`: `:root` (light) and `.dark` (dark). `App.tsx` toggles `html.dark`, so portaled sheets, dialogs and toasts get the same values.

- Product CSS uses the editorial tokens (`--paper`, `--ink`, `--ink-2`, `--muted`, `--line`, `--strong-line`, `--accent`, surface roles, `--tone-*`, `--attr-*`, `--ok-*` / `--warn-*` / `--error-*`, `--page-*`). shadcn tokens (`--ui-muted`, `--ui-accent`, `--popover`, …) are only for `components/ui` primitives.
- A new token goes into both `:root` and `.dark`. No per-component palettes, no `var()` hex fallbacks.
- `--faint` is for icons and hairlines, never text.
- Tones: `--tone-include` green = done or included; `--tone-uncertain` amber = partial or needs attention; `--tone-exclude` red = blocking failure or excluded; `--accent` = live work or current selection; `--muted` = waiting or secondary.
- Text on a tinted notice uses the matching `-ink` token (`--warn-ink`), never the tone itself.
- **Contrast first.** Text stays at 4.5:1 on every surface it can sit on (paper, sidebar, hover, selected, accent tint, bubble; in dark also raised and field surfaces). Several light tones are darker than Elicit's for this reason.

Key values: paper `#fff` / `#16181b`, ink `#1f2328` / `#e7e9ec`, accent `#3b5b9a` / `#93acdf`, citation mark `--mark` `#fdf1b8` / `#5a4d17`.

## 4. Type, shape, icons

- **Fonts.** Inter Variable (`--font-sans`) carries everything. Source Serif 4 (`--font-serif`) only for the report title and its emphasis. Both are bundled from `@fontsource-variable`; no network font requests. Identifiers (DOI, run ID) use the system monospace stack. CSS writes `var(--font-sans)`, never a family name.
- **Sizes.** Pick from 10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 14.5, 15, 16, 17, 18, 22, 24, 27, 28. Weights 400–650.
- **Sentence case** for every label. No uppercase eyebrows or `text-transform`.
- **Radii.** 5–7px controls and chips, 8–10px panels and dialogs, 12px composer, 999px pills.
- **Borders and depth.** Structure is 1px `--line` hairlines; controls use `--strong-line`. Shadows (`--shadow-float`) only on floating layers: dialogs, popovers, toasts, quick find, composer, selection bars. In-flow content gets no shadow and no colored side bar.
- **Icons.** lucide, stroke style, `aria-hidden`. No emoji or unicode glyphs as icons.
- **Model names.** Show the display name with its connection icon (`ModelName.tsx`, `useModelText()` in `modelText.ts`) and effort as a label ("GPT Luna · Medium"). The raw ID goes in a details disclosure. Same for scholarly providers.

## 5. Evidence in the UI

- A source's title opens `PassageSheet` (Source details) wherever the source is listed. There is no second details surface.
- A citation chip opens the exact stored passage and source version, never a work-level record. A PDF citation opens the whole plain-text document on the cited page, using its exact extraction ID.
- Mark only the backend-located anchor (`mark.citation-highlight`, `--mark`). A mark may widen only to keep a formula or table whole. Never guess a span.
- If the anchor cannot be located, mark nothing, tint the page amber and say the text should be checked in the PDF.
- Limits, unanswered parts, source text, analyst inference and reviewer verdicts look different from supported claims.
- Different versions of a work stay separate. Abstract only, PDF, inaccessible, version uncertain and removed are written in text, never color alone.
- Citation count, venue, recency and similarity are ordering signals, never quality.
- The user's include/exclude decision outranks the model's proposal and keeps its reason.
- "Semantic support not checked" appears once per surface, as neutral fine print.

## 6. States

| State | Pattern |
| --- | --- |
| Loading | Short text with `role=status` |
| Live model work | Shimmer, spinning icon or sweep, always with text |
| Empty | One muted sentence: what is missing and the next action |
| Attention | `<Notice tone="attention">`: amber icon and what to check |
| Error | `<Notice tone="error">`: cause and recovery, `role=alert` |
| Success | Toast that says what changed |

- In-page notices use `Notice.tsx`. Confirmations use `ConfirmDialog.tsx`, nothing else.
- A disabled control always has a visible or accessible reason (`aria-disabled` plus a description, not `title` alone).

## 7. Motion

- Motion only shows a state change or live work. 100–200ms for feedback, 1.6–2.2s for live loops. Ease out, no bounce, no layout shift.
- The typewriter research title is the one signature transition.
- Every animation has a reduced-motion path. `index.css` has a global `prefers-reduced-motion` block. Script scrolls use `scrollBehavior()` from `motion.ts`; never hard-code `'smooth'`.

## 8. Layout and responsive

- Main breakpoint 760px: sidebar becomes a drawer, a 46px phone bar holds menu, language and theme, dialog actions stack.
- No global header. Sidebar holds navigation, recent research, access state, language and theme.
- Sheets are base-ui Dialog side sheets, about 56% wide (full width on a phone), with a 46px head. No sheet inside a sheet except evidence inspection.
- Adapt hierarchy, not just size. Never truncate evidence-critical text (titles, passages, locators, failure reasons, version labels) without a way to reveal it.
- The page never scrolls sideways; wide tables scroll inside their wrap.

## 9. Copy and accessibility

- All strings go through `t(englishKey, vars)` in `i18n.ts` with the Turkish map beside it. Label records live in `labels.ts`. Dates and numbers use `uiLocale()`.
- Plain, declarative, sentence case. Buttons name their action ("Use this value"). Never imply a check DEIXIS did not do.
- No env-var names (`DEIXIS_*`) in UI copy.
- Focus is a 2px accent outline with 4px offset. Tabs, grids, listboxes and live regions use the right ARIA roles.

## 10. Exceptions and drift

Deliberate:

- Shadows and scrims use literal black-alpha values (same in both themes).
- The 3px accent gutter mark beside a cited paragraph in the plain-text document.
- Hover shadow on Home cards and Connections tiles.
- The 2px `--strong-line` left hairline on a quotation in the cell panel.
- `--attr-submitted` (light) looks close to `--tone-uncertain` after the contrast fix. Both carry text; the owner decides whether to separate them.

Known drift (fix when touching the file):

- Literal `#fff` and accent hexes remain in `Home.css`, `App.css` and `research/kit.css` (white text on the composer band and filled buttons). New code uses tokens.

## 11. Before landing a UI change

1. Read the component and its CSS first; reuse classes and tokens.
2. Remove CSS rules your change leaves unreferenced.
3. Keep the stack: React 19, Tailwind 4, base-ui/shadcn in `components/ui`. No new UI dependency for local styling.
4. Run `npm run build`, `npm run lint` and the relevant Playwright tests.
5. Look at the screen at desktop width and at 390px, in light and dark.
6. A change that breaks a rule here either gets fixed or is recorded in §10 with its reason.
