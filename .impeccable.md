# DEIXIS Design Guide

This guide covers the web UI in `apps/web/src`. It records how the interface is built today and the rules every change must follow. It was rewritten on 2026-09-17 from a survey of the code. On 2026-10-11 the colours, fonts and direction changed to the owner-approved mockup (D5 in `docs/decisions.md`); the sections below say what that changed.

Each statement is one of two kinds:

- **Rule.** It holds for all UI. The code follows every rule in this guide as of 2026-09-17; keep it that way.
- **Current.** A description of what the code does now, given so it can be reused.

Known drift is listed in §10. A change that breaks a rule is either fixed before it lands or recorded as a deliberate exception in §10.

## 1. Context

### Users and jobs

Academic researchers use DEIXIS to search for literature, screen it, inspect it, compare it, and write source-linked syntheses. They work with long questions, many source versions, and partial access, and they care where every piece of evidence came from. The interface supports long reading sessions and checking evidence; it is not a conversational AI product.

Core jobs:

- Ask a research question or revise it without losing earlier revisions.
- Tell apart sources that were retrieved, screened in, included, inspected, given to the model, and cited.
- Read the answer or report as the main deliverable while the process stays auditable.
- Go from a claim to the exact cited text, inside its whole document, and from there to the PDF page.
- Build and check an evidence table cell by cell.
- Understand incomplete access, failed or unknown operations, stale results, and unchecked output without opening developer diagnostics.

### Personality and direction

The interface is calm, trustworthy, and plain. It is light-first, with a full dark theme. It should feel like a quiet research desk, not like a dashboard or a chat application.

The owner chose Elicit's layout and density on purpose (D5): a white page, a light side rail, small sans type, hairlines and few containers. The difference from Elicit is the DEIXIS ink blue accent (#3b5b9a light, #93acdf dark) where Elicit uses teal, and the evidence rules below, which Elicit does not have.

**Rule: the mockup is the visual specification (D8).** The clickable mockup v24 (`.local/design/elicit-style-mockup/index.html`) defines every screen: layout, order, sizes, wording and icons. Fixed UI is copied exactly; example data (titles, counts, model names, the institution, the person's name) comes from real records, and a list has as many rows as the data has. Controls that only operate the mockup (the state switcher, "Mockup · example data" tags, "Use the example setup", "Reset the mockup", "Mockup:" notes) are not built. A sentence names only the operation that was done and measured: mockup copy that would be false changes, the layout stays. Contrast beats colour match. A live feature with no mockup element goes into the nearest mockup container in mockup style. Every allowed difference is listed in `apps/web/e2e/parity/exceptions.ts` with the rule it cites; the parity check (`npx playwright test --project parity`) fails on anything else. Screens not yet ported are pending pairs in `parity-map.ts`, and the slice that ports a screen turns its pairs on. Where this guide still describes the older structure (tabs, sheets), it describes the current code until that slice lands.

### Principles

- State is explicit, including failure, uncertainty, and "not checked".
- The deliverable (answer, report, or table) comes first; the process (runs, steps, usage) sits one disclosure level deeper.
- Hierarchy comes from type, weight, spacing, and hairline dividers. Containers and shadows are used only where a surface actually floats above the page.
- A visual state comes from recorded backend state. Copy never claims more than the evidence contract supports; for example, "located" never becomes "verified".
- Every change works in both themes, at narrow widths, with the keyboard, and with reduced motion.

## 2. Foundations

### 2.1 Tokens

**Current.** Both token sets are defined once, in `index.css` on `:root` (light) and `.dark` (dark). `App.tsx` toggles `html.dark`, so every element, including portaled sheets, dialogs, popovers, and toasts, gets the same values without redefining them.

| Set | Names | Used by |
| --- | --- | --- |
| shadcn | `--background`, `--foreground`, `--primary`, `--ui-muted`, `--ui-accent`, `--border`, `--input`, `--popover`, `--card`, … | the `components/ui` primitives through Tailwind utilities (`bg-muted` resolves to `--ui-muted`, `bg-accent` to `--ui-accent`) |
| Editorial | `--paper`, `--ink`, `--muted`, `--line`, `--accent`, surface roles, semantic tones, source attributes (`--attr-*`), state notices (`--ok-*`, `--warn-*`, `--error-*`), document page (`--page-*`) | all product CSS |

shadcn's muted and accent surfaces are named `--ui-muted` and `--ui-accent` so they do not collide with the editorial `--muted` (secondary text) and `--accent` (brand blue).

**Rules:**

- Product CSS uses the editorial tokens. Use shadcn tokens only when styling a `components/ui` primitive or a popover built on one (`--popover`, `--ui-accent` for a highlighted option).
- Do not redefine editorial tokens on a component or surface, and do not add per-component palettes. A new token goes into both `:root` and `.dark` in `index.css`.
- `.dark` also sets `color-scheme: dark`, so native checkboxes, radios and selects render in their dark form; a checkbox or radio still sets `accent-color: var(--accent)`.
- Product CSS has no literal colors. The only exceptions are black-alpha shadows on floating layers and scrims (§10). Do not give `var()` a hex fallback.

Before changing a text colour, check it against every surface it can sit on: `--paper`, `--sidebar-surface`, `--hover-surface`, `--selected-surface`, `--accent-tint`, `--bubble`, and in dark also `--raised-surface` and `--field-surface`. **Document pages** (figure frames, the PDF page) use `--page-surface`, `--page-ink`, and `--page-muted`.

### 2.2 Typography

**Current fonts:**

- Inter Variable (`--font-sans`) is the one sans. It is set on `.app` and on portaled surfaces, and it is shadcn's `--font-sans`, so Select and Dropdown popups, Tooltips, and the model palette render in the same face. Do not load another sans.
- Source Serif 4 Variable (`--font-serif`) is the only serif, with an italic file for emphasis.
- Both come from `@fontsource-variable/*` at fixed versions and are bundled; the app makes no font request to the network. Product CSS writes `var(--font-sans)` or `var(--font-serif)`, never a family name.
- KaTeX math uses KaTeX's own bundled fonts.
- No monospace font is loaded. DOIs, run IDs, and code use the system stack `ui-monospace, SFMono-Regular, …`, and only for identifiers, never for decoration.

**Rule: the sans carries everything; the serif marks the report as a document.** Claims, passages, source titles and headings are set in Inter. The serif appears only where the mockup has it.

Sheets, the report and the research header follow the mockup's smaller scale. The Home headline and collection pages keep the sizes they had before D5 until their port slices land.

**Rules:**

- A new size should come from the scale 10, 10.5, 11, 11.5, 12, 12.5, 13, 13.5, 14, 14.5, 15, 16, 17, 18, 22, 24, 27, 28 (plus the display clamps). Do not add another half-pixel size.
- Weights in use are 400, 450, 500, 550, 600, and 650, plus 420 and 470 for display text. Prefer 450 or 500 for titles and 550 or 600 for interface emphasis.
- Display text is tracked tight (−.01 to −.035em). Small labels get at most .06em positive tracking.
- Set headings with `text-wrap: balance`. Keep reading measure at 64–76ch.

**Rule: labels are sentence case.** No uppercase eyebrows, kickers, or column heads, whether through the copy or through `text-transform`. Labels get their weight from size and weight, not from capitals or tracking ("Research · revision 3", "Source-linked answer", "Add sources", "Recent research").

**Rule: a Library row reads as a table line.** The title is 14px/500 ink, the byline and the venue (italic) are 12px muted below it, and the pills are quiet outlined tags; the title alone reads as the content and the byline as its record.

### 2.3 Shape, borders, depth

- **Radii (current):** 5–7px for controls and chips, 8–10px for panels, dialogs, and table wraps, 12px for the composer, 999px for pills. Stay within this set.
- **Borders:** in-flow structure uses 1px `--line` hairlines. Controls use `--strong-line`.
- **Rule: shadows only on floating layers**, and new ones use `--shadow-float`. Floating layers are dialogs, popovers and the model palette, toasts, quick find, the composer, the library drag dock, and the selection bar. Content in the flow of the page (cards, notes, buttons, rows) gets no shadow, no hover shadow, and no translate press effect.
- Never use a colored side bar thicker than 1px on a card, note, or callout; a flag or notice uses an icon plus text. The one exception is the 3px citation gutter mark next to a paragraph in the plain-text document, which marks a text location, not a container.

### 2.4 Icons

- **Rule:** use lucide icons, stroke style, with `aria-hidden`. No emoji or unicode glyphs (›, ▸, ×) as icons; disclosure chevrons are `ChevronRight`/`ChevronDown`.
- **Sizes by context:** 12–13px inline with metadata, 14–15px in buttons, 16–17px in navigation, 18–20px as a sheet or section mark.
- **Rule: every model name shown in the interface has its connection icon.** The icon comes before the display name, as one non-wrapping unit; the icon is decorative and the name stays as text. The same applies to scholarly providers (OpenAlex, Semantic Scholar, …) and to DOI links.
- **Rule:** show the model's display name from its connection's model list, not the raw ID, with a reasoning effort written as a label ("GPT Luna · Medium", never `gpt-5.6-luna-medium`). The raw ID belongs in a details disclosure.
- **Current:** `useModelText()` (`modelText.ts`) turns a stored model ID and effort into that text. It shares one fetch of the connections list and falls back to the ID for a model no longer listed. `<ModelName connection text />` (`ModelName.tsx`) renders the icon, a screen-reader connection name, and the text. The transcript run models, evidence run line, report "Model:" line, reviewer note, and cell provenance use them; the model palette and the composer models summary already hold display names and place `ConnectionIcon` themselves. A model named inside a translated sentence (for example the recheck scope) uses the text alone. Size an icon by setting the `.connection-icon` box itself; its default box is 18px.

## 3. Shell and shared surfaces

### Shell

- **Sidebar.** Fixed, 256px wide (224px at ≤1050px), on `--sidebar-surface` with a hairline right edge. At ≥761px it can be dragged between 200 and 420px and collapses to a 56px icon strip; the collapse state and width are kept in `localStorage`. At ≤760px it becomes a drawer with a scrim.
  - The resizer has `role=separator` and arrow-key support.
  - Contents, top to bottom: brand (18px mark and a 16px/600 wordmark in `--accent-deep`, `--accent` in dark) with the collapse button; Search (⌘K) and the navigation as 13.5px rows (7px 10px padding, `--hover-surface` on hover, `--selected-surface` when current); the collapsible "Recent research" list in sentence case, each row (34px) a status icon (a completed run is a bare check, no ring), the title (13px `--ink-2`, ink on the open research) and a relative time that gives way to the row's ⋯ button on hover and focus; the open research shows both its time and the ⋯ button; then the foot. The brand row is 54px (14px top, 10px bottom padding).
  - **Foot.** Above a hairline: the background-work card (`.bgcard`), institutional access as a status dot and one line (the longer note goes to the title and screen readers), and a row with the TR/EN switch and the theme button. In the collapsed strip the foot keeps the access dot, the switch (stacked) and the theme button.
  - No user avatar or name, no global "awaiting you" count and no shortcut sheet: there is no data behind them.
- **No global header.** Each view starts 32px below the top edge (20px under the phone bar), except the research view: its 46px topbar sits at the top edge, directly under the phone bar on a phone. Theme and language live in the sidebar foot on wide screens. On phones a 46px bar holds the menu button ("Open navigation"), the brand, the TR/EN switch and the theme button; the sidebar's own copy is hidden there so each control exists once. The theme is system, light, or dark, stored in `deixis-theme`, and applied as `html.dark` plus `.app.dark`.
- **Copyright and source link** sit at the end of the Settings page, not on every page.
- **Page widths.** Home is one centred column, 700px wide, starting about 11vh from the top. Above 761px, research and collection pages are full width with `clamp(32px, 4vw, 80px)` gutters and paragraphs capped at 76ch. The Trash page is 960px wide and centered, and the Library page has no max width.

### Sheets

Sheets are base-ui Dialog side sheets. Portaled surfaces get a `dark` prop and add `.dark`.

Every sheet uses the shared panel base (`.detail-sheet` in `App.css`, panel rules at the top of the report block in `workspace.css`): about 56% of the window (min 420px, max 100vw, so full width on a phone), and `.is-full` gives 100vw. Source details is the only sheet with an expand button; it widens to `.is-full` and caps its text at 820px. The report document is a 680px column inside its sheet.

**Rules:**

- **Rule: a source's title opens the source sheet.** Wherever a stored source is listed — the Sources tab, an answer's references, an evidence row, the Library, the Trash — its title is the control that opens `PassageSheet` (“Source details”) on that source's passage or PDF, so one surface shows the record, its reading depth and its text everywhere. There is no second details surface: a work with nothing stored to read says so instead of opening an empty one.
- A sheet has a 46px head with a hairline below: an optional 16px muted icon, the title in sans at 13.5px/500, then 30px icon buttons (expand where it exists, close). A visible description, or the cell panel's source line and pills, sits under the title inside the head. The body scrolls; the head never does.
- The report sheet's head is its toolbar: icon, the report title with an ellipsis, then quiet 30px text buttons for the existing controls (Reviews, Copy, Download; Evidence view and the Markdown/LaTeX exports on an evidence report). On a phone the head stays one 46px row: the title gives way first, and Copy, Download and Evidence view drop to 30px icon buttons whose text stays as their accessible name (`.report-head-label`); only an evidence report with every control may still wrap. Export labels drop to icons when the sheet is narrower than 820px.
- Inside a sheet, `.ref-pill` is neutral: grey 11.5px text on a 1px hairline, radius 5px, no icon; reading depth, version or OCR shows only as a 6px dot in the pill's tone. Pills without a tone (version not stated, uploaded by you) have no dot.
- Persistent actions for the sheet's subject go in a footer pinned to the bottom, not at the end of a long scroll (see §4.8).
- Do not open a sheet inside a sheet for anything except evidence inspection. Evidence inspection from the cell panel opens the source sheet on top.

### Dialogs, toasts, and quick find

- **Dialogs.** `ConfirmDialog.tsx` is the only confirmation pattern, used everywhere including Trash: 440px, a 32px mark tile (red TriangleAlert, or accent Info when `neutral`), an optional one-line context row, and actions stacked full width at ≤760px. `.confirm-dialog` is defined once, in `workspace.css`.
- **Toasts.** One at a time, bottom-right, 380px. Errors stay until dismissed; a toast with an action stays 12s; others stay 5s and pause on hover or focus. A toast confirms what happened ("Value saved.") and may offer Undo.
- **Quick find.** 620px, opens at 12vh from the top, a grouped listbox using `aria-activedescendant`.

### Tabs

- Research tabs sit under the 46px topbar: 12.5px/500 muted labels with 7px 10px padding, the active tab in ink with a 2px **accent** underline, and counts as plain muted numbers after the label (no pill).
- **Rule:** every underline tab set uses the accent underline and the same size and weight. A hand-built tablist uses the shared `.tab-strip` class (`aria-selected` for the active tab, `aria-disabled` for an unavailable one), styled like the research tabs; the source-view "Plain text | PDF" tabs and the Settings tabs use it.

## 4. Surfaces

### 4.1 Home and question intake

- The page opens with the composer, not a chat transcript or a headline. The page's `h1` (set per language) and the intro sentence are visually hidden; the `h1` stays in `main` because route changes hand focus to `main h1`. The composer's "What would you like to investigate?" label is hidden too; the textarea is named "Research question".
- The composer keeps the original intake DOM and Tab order (textarea, Add sources, Source scope, Research depth, models summary, Start research). The look below is CSS only: the band is the box's 42px top border, and the scope trigger stays inside `.composer-options` and is positioned onto it.
- The composer is a floating box (radius 12, `--shadow-float`, 1px `--accent-band` border; on focus the border turns `--accent` with a soft ring). Top to bottom:
  - a band in `--accent-band` carrying the Source scope control as a white 28px button on an opaque band-plus-white background (white text and icons, ≥4.5:1, white focus outline);
  - the textarea, 15px/1.55 (16px on phones), 14px 16px padding;
  - a control row on `--sidebar-surface` with a hairline top: the Add sources menu (+, 30px square), the Research depth control and the models summary (30px, hairline border, page surface; one compact "Models ⌄" button at every width, the chosen model names kept as its accessible text and shown in the popover), and a 32px square send button in `--accent`. Attachments sit just above it on the same surface as a line of 28px file chips (icon, name, size or "guides the search", remove); several PDFs wrap. No radios: every eligible PDF guides a mixed search (D3).
  - the models summary expands to per-role model pickers in a second row on the same surface.
- Under the composer, centred 12px `--muted` text: the scope caption and the ⌘ / Ctrl + Enter shortcut, then the no-connection and error notices. When semantic search is off only because nothing is saved in Settings, no Gemini key is set and the built-in model is not downloaded, one info notice says so and offers "Download the built-in model" (D7); it shows the download's step while it runs and goes away once the model is ready, which makes it the one used. It never shows after the person chose Off. No example chips, suggestion or resume cards, and no setup card: there is no data behind them.
- The model palette is a 440px searchable popover grouped by connection, with a preview footer. At ≤520px it becomes a bottom sheet.
- Ask one clarification only when ambiguity would change the search or answer scope. Otherwise proceed with an explicit interpretation.

### 4.2 Research header

- Before an answer exists, the question is the provisional title. A valid answer supplies a descriptive title of **at most 15 words** in the answer language; the backend enforces this limit and the "Suggest a short title" action promises it.
- A newly arrived title is revealed with the typewriter transition (about 28ms per character, clamped to 0.6–2.6s, only when the text changes). With reduced motion the full title appears at once. This is the only signature transition in the product; nothing else animates around it.
- Found, unique, included, inspected, given to the model, and cited are separate counts. Never merge them into one progress number.
- **Topbar.** One 46px row with a hairline below holds the title (13.5px/500, the page's `h1`), the live run strip (status pill, Pause, Resume, Cancel) or a run chip that links to the tab controlling that run, and the research actions: "Suggest a short title" while the question is still the title, "Revise question" and the Export menu. At ≤760px the title keeps the row with Export, and "Revise question" and "Suggest a short title" become 30px icon buttons whose text stays as their accessible name (`.research-topbar-label`) and tooltip. The row still wraps when a live run strip is present, and the strip wraps inside it, so a long status never overflows at 390px. When the tab strip scrolls sideways (phones), the selected tab is scrolled into it, on selection and on resize; only the strip scrolls, never the page. The tabs follow directly under it.
- Revision, scope, and depth stay compact under the tabs. Model provenance lives in the run foot and the report, not in the header.
- The title is renamed **in place**, never through a button in the header: double-click the heading, or focus it and press Enter or F2. The sidebar row's action menu carries the labeled **Rename** path for assistive technology. The field restates the heading's type recipe (Inter 500, 13.5px, line-height 1.4) and grows to fit its text, so the topbar does not move when editing starts.
- While editing, the section label's row carries the hint — "Enter saves, Escape cancels", plus a "N of 160 characters" counter past 120 characters — so the counts below never shift. Enter or blur saves, Escape reverts.
- A user title is not final: a later valid answer may replace it with the model's descriptive title.

### 4.3 Activity timeline (transcript)

- **Current:** the conversation is one centred 640px column. The question renders as a right-aligned bubble on `--bubble`. Each run is one `.chat-turn` with no rail or nodes:
  - a toggle row with the label, start time, and duration;
  - a live plan note;
  - the frozen-protocol note ("Nobody reviewed the search vocabulary…") is a flat 13px line with a chevron, aligned with the run's chevrons, not a bordered card;
  - a flat step list: an 18px status icon (done in green, running in accent, attention in amber, waiting as a dashed circle), a 13px step line with its time at the right, and an opened step's note indented under a 1px left hairline;
  - a foot line with the models (icon plus name), spend, and Pause.
- **Rules:**
  - One run is one timeline item. Its plan, steps, usage, and errors expand inside that item.
  - A phase that contains a failed or outcome-unknown operation never looks wholly successful because a later phase finished.
  - A run note (`.chat-note`) takes its tone from the run: paused is amber (attention), failed is red (`.is-error`), cancelled is neutral (`.is-neutral`), because a cancelled run was stopped on purpose.
- The `chat-*` class names are historical. The timeline explains the process; it is not where the answer is read.

### 4.4 Answer and report

- **Current:** A candidate review opens in its own sheet from the candidate detail panel. Reviews are an in-flow mode of the target's own sheet; the document keeps its reading position when the mode closes. A preview exposes the frozen input and call bounds before Start. Located source quotations remain distinct from reviewer inference, and findings carry snapshot text, target-specific stale reasons and append-only decisions. Accept records a decision; only the editable, dependency-checked apply save changes a report claim. Uncertain writes retain their exact body and key for Retry. Passage inspection is the only additional sheet opened from this mode.
- **Current:** the Answer tab shows a report artifact card (mini serif preview, "Report · VN"; no sparkle before the label and no ↗ arrow, on table and evidence-report cards too). The card opens the report sheet: the toolbar in the panel head (Reviews, Copy, Download), then a 680px document with the serif title, one meta line ("Report · VN · date"), sections, "Not answered", "Limits", and "Cited passages" (export and citation style beside the heading, then a numbered reference list: number, source key, the formatted reference, neutral pills with a coloured dot).
- **Rules:**
  - The report reads as a research document: a serif title, sans claims and section headings, and inline citation chips (`.cite-chip`) showing the source key, or "key, p. N" when a claim cites more than one passage of a source. A chip is neutral: 11.5px/400 `--muted` text on `--hover-surface` (ink on `--selected-surface` on hover, accent focus ring); the accent tint belongs to the highlighted anchor (`mark.citation-highlight`), not to the chip.
  - A citation marker opens the exact stored passage and source version, never a work-level record.
  - Limitations and unanswered parts are visibly separate from supported claims. Source-stated text, analyst inference, and reviewer verdicts are visually distinct.
  - The closing provenance line says what was checked structurally and that semantic support was not checked. The model named there gets its connection icon.
  - Copy, download, and citation style belong to the report surface and stay secondary to reading.

### 4.5 Sources and screening

- The state filters (All, Included, Undecided, Excluded, with counts) are an underline strip; under it one toolbar row holds Select shown, the text filter, the PDF filter and the sort. A source stays a row (`.source-row`), not a table line.
- The source title (14px, weight 500) and the source key are the first reading line. Authors, venue (italic), year and citation count follow at 12px muted (`.source-byline`). Version, access, provider and similarity are neutral hairline pills (`.source-status .source-fact`) whose dot carries the canonical tone (§2.1); the text names the attribute.
- The model's proposal is one line of text, its verdict in the tone colour. The decision control (`.selection-toggle`) is a segmented Include / Undecided / Exclude; the chosen segment takes the matching notice surface and ink (`--ok-*`, `--warn-*`, `--error-*`). Row actions are accent text buttons; Remove PDF keeps the destructive tone. A picked row takes `--accent-tint`; the exclusion reason sits in a band on `--sidebar-surface`; the selection bar is on `--sidebar-surface` with `--shadow-float`.
- Queue pills (list and detail) are neutral like the sheet pills: grey text on a hairline, the version's tone only as a 6px dot; on the selected row the text is `--muted` mixed 25% toward ink. The detail title is 15px/500 without `balance`, so a long title fills the column.
- The queue's open row is a bordered card whose meta line is a band on `--sidebar-surface`; the two reads sit in two bordered boxes and the answers in the card foot as full-width 36px option rows (labels unchanged, the primary answer filled). Lists of works in PDF readiness and Waiting for your PDF are one bordered box with rows on hairlines (the waiting rows denser: 8px padding, 13.5px title, 12px byline and place number); reading-depth counts sit in hairline cells; the drop zone is a dashed box with centred text. The Flow block's count lists are bordered boxes with a head band.
- The user's include, exclude, or undecided decision outranks the model's screening proposal and keeps the user's reason.
- Citation count, venue, recency, and similarity are labeled as metadata or ordering signals ("Used for ordering only; it is not a relevance judgment."), never as quality.
- Different versions of one work stay visibly separate. Abstract only, PDF available or attached, inaccessible, version uncertain, and removed each need explicit text, never color alone.
- **Current.** Each eligible PDF row shows its latest recorded text retry or file restore, one explicit text-retry action with accessible disabled reasons, and a dated recovery-history disclosure. File restoration and text extraction remain separate outcomes; history states what each operation did.

### 4.6 Source details and citation inspection

- The header block is one meta line (source key as plain 12.5px `--ink-2` text followed by "·", venue, year, "cited by N (OpenAlex)"), the title (17px/600), authors in grey 12.5px (first two plus "and N more"), neutral pills for version, access or text kind, and OCR, and the DOI or publisher link as a pill-sized link. Below it, screening, similarity and the latest-answer role form one grey line (`dl.source-role` laid out inline); only the screening value carries its tone. Then the "Plain text | PDF" tabs. The footer is one muted 12px line, "Found via … · Added …", above a hairline.
- **Current.** The sheet has no primary button: the PDF tab is the way to the PDF, and finding or attaching a PDF lives in the source row and the waiting tab. D8 brings in the mockup's Open/Find PDF, Copy citation and ⋯ menu as the source-details panel's action row (parity slice S12).
- The source sheet opens on **Plain text** by default.
- **A citation to a PDF passage opens the whole plain-text document** of that file on the cited page:
  - A sticky strip reads "Cited text · PDF p. N" and has a "Go to cited text" button. It is a neutral bordered bar (`--line` border, page ground, muted icon, outlined button); an unmarked citation keeps its amber tint.
  - **Rule.** A PDF citation requests its exact extraction ID, even when current, and opens that extraction's stored text. A missing or mismatched occurrence falls back to the stored single passage. "Show current text" offers a comparison without anchor marking or cited-page tint; "Back to cited text" restores the cited view. An earlier-extraction notice states the recorded input relation to the file's recorded hash and whether a file restore followed the read. The PDF tab names the stored file and its possible difference from the parser input for a non-current, restored-after or unmatched-input occurrence. Figure pictures are withheld in the cited non-current view; stored captions state that a picture would come from the current file.
  - Abstract-only records and passages of a replaced or removed file keep the single-passage view.
- **Highlighting:**
  - Mark only the backend-located anchor, found with the same normalization the backend uses (case, spacing, punctuation, and hyphenation ignored). The mark is the mockup's yellow `--mark` (#fdf1b8 light, #5a4d17 dark; D8 replaces D5's accent tint) under `--ink` text, with a 3px accent gutter mark beside the paragraph. The class name stays `citation-highlight`; the claim-candidate sheet uses the same mark.
  - A mark may widen only to keep a formula whole. An anchor inside a table frames the whole table.
  - Never guess a span or widen a mark to a guessed sentence.
- If the anchor cannot be located, mark no text. Tint the cited page faintly amber, turn the strip amber, and say the text was not marked and should be checked in the PDF.
- If a stored citation has no anchor at all, say it cannot be highlighted and that a new answer repairs it.
- The plain-text document keeps real paragraph structure and repairs layout-only line breaks. It includes:
  - a contents disclosure (when there are 3 or more headings);
  - the title and section headings in the sans at 17 / 15 / 13.5px, weight 600, over 13.5px body text;
  - figures cut from the PDF page in a white frame with an honest caption;
  - Marker tables as bordered tables;
  - in-text references to figures, tables, equations, and [n] as accent-underlined jump links, with reference entries in a tooltip;
  - an author-notes toggle.
- Notices in this sheet explain OCR text, Marker page reading, equations to check, removed sources, and earlier extractions. Each notice says what the reader should check.
- The PDF tab is disabled when there is no PDF. It stays focusable with `aria-disabled`, its reason is in a Tooltip for sighted users, and the same reason is linked through `aria-describedby` to a screen-reader-only element.

### 4.7 PDF viewer

- PDFs render in the DEIXIS viewer, never in the browser's native PDF chrome. The bibliographic header and the tabs stay above the document.
- The toolbar is quiet, 44px tall with 30px icon buttons: previous and next, a page input with "/ N", zoom (60–240%), and a download link, all with accessible names. It opens on the cited physical page and fits the page width on a white page over a lightly tinted ground.
- **Rule:** choosing the PDF tab, or opening the sheet on the PDF view, expands the sheet to the full workspace width. Returning to plain text keeps the width the user left it at; the expand button still toggles it.
- At narrow widths, hide zoom before page navigation or download.

### 4.8 Evidence table and cell panel

**Table (current):**

- A bordered wrap (radius 10, `--line`, paper ground) with a sticky 340px source column (152px at ≤600px). Header cells sit on `--sidebar-surface`; cells are 13px on `--line` hairlines; the cell whose panel is open is tinted `--accent-tint` (`td.is-open`).
- "Model actions locked" is an amber pill (`--warn-ink` on `--warn-surface`). Suggested columns are one box with a head band on `--sidebar-surface`. CSV export of current values stays in the toolbar. The toolbar is one left-aligned flow of uniform outlined 32px buttons (`--strong-line` border, page ground, 13px, 10px side padding) that wraps as needed, at every width; only "Fill empty cells" keeps the filled primary look while it can run.
- Cells are 190–270px wide with a minimum height of 68px, and the value is clamped to 4 lines.
- The grid supports arrow-key focus (`role=grid`), has a fullscreen mode, and shows a live run line with the model chip (icon plus name).
- The empty state shows start cards, a fading ghost table, and template choices.

**Cell panel (rules).** Implemented in `EvidenceTable.tsx` (`CellPanel`).

- **Header.** The column name is the title, after a table icon. The source identity sits in the header too: source key chip, the source title, year, then neutral pills for version and reading depth. The body does not repeat it.
- Section labels are sentence case ("Current value", "Evidence", "Pending proposal").
- **Value.** The cell value leads the body: 17px/600, balanced. Under it, one quiet provenance line gives author (model proposal or your value), model icon and display name, and date. Model ID, column definition, reading source, and run ID sit behind a "Details" disclosure.
- **Reading depth.** A limit ("Read from the abstract only.", "Read from the metadata only.") appears directly under the value, in amber with an icon and text.
- **Evidence.** It reads like the mockup's citation list, not a control: each passage is a 13px quotation behind a 2px neutral left hairline (`--strong-line`) with the anchor tinted in accent, rows separated by hairlines, and a quote count in the section label. Under it comes a locator caption (reading depth · source key) and a quiet accent text link, "Open in source", that opens the whole document at the anchor (§4.6). No outline button beside the quote and no card around it.
- **Actions.** Edit and Recheck live in `footer.cell-foot`, pinned to the bottom of the sheet. The footer also holds the recheck scope as one line (source key · passage limit · model icon and name · number of calls · "the result waits as a proposal; the model does not see the current value") and, last and faintest, the "semantic support not checked" note. That note appears once.
- **While this cell's own recheck runs,** a live accent status sits under the value, a dashed proposal slot is reserved with a restrained shimmer, and the footer scope line reads "This cell is being rechecked…". "Another run is active" is only for a different run.
- **Pending proposal.** Current and proposed values sit in two columns, with the proposal side faintly accent-tinted. "Use this value" is the only primary button, and "Keep current" is secondary. The note under it says that using a proposal records a decision and does not check support. The columns stack at ≤440px.
- **Flags** (stale column, PDF removed or replaced, OCR numbers unchecked, earlier extraction) are amber text notes with an icon; a proposal that failed validation is red. None of them use a side bar.
- **History** is a disclosure with a chevron and a count.

### 4.9 Library, Trash, Connections, Settings

- **Library.** One page for every stored work, grouped by the project that holds it. A masthead (h1 plus one line saying what the Library is) sits above a reading-depth rail of three counts, a coverage bar whose widths follow each depth's share, and a command row of search, sort, reading-depth filter, grouping and density. The rows of a band sit in one bordered list (10px radius, hairline separators, hover tint) and read as a quiet table: source key, then the work's title in sans 14px/500, then the 12px muted byline with the venue italic, then the reading-depth pill (an outlined tag whose tone is a 6px dot: PDF text blue, abstract grey, metadata muted), the stored versions, the date it was added and the provider's citation count with the date it was read. A project band head is sticky, carries the select-all checkbox, a fold caret, the title, the drop note, the band facts and "Open research" with its overflow menu on hover or focus, and is a drop target while a row is dragged, as the dock is. A row opens the source sheet on the version a research still holds — its PDF, else its abstract — and a metadata-only work says so in a toast instead. A picked work joins the selection bar above the dock; the pager sits under the list, and a key strip under the pager names `/`, `↑↓`, `x` and `↵` (hidden where there is no hover pointer). At ≤760px the bars run gutter to gutter, the grip is dropped, density keeps only title, byline and reading depth, and the sheet holds the rest.
- **Trash.** A 760px centred column like Settings: a 20px/600 h1, groups headed by 14px/600 sans h2s with a muted count, and the research, table and template rows of a group as one bordered list (the Settings row-group look) with an outlined Restore and a Delete permanently button in the error colour (`--error-ink` text, `--error-line` border). A selection bar serves the removed sources. Destructive confirmations use ConfirmDialog. Under the page lede, `.trash-index` says in one line what the Trash holds and links to each group.
  - The removed-sources group holds hundreds of rows, so it carries a sticky tool row (filter field, All/Deletable/Still cited chips, and — from two research on — a Research picker and a Sort order: recently removed, title, year), one block per research, and at most eight rows before “Show N more”.
  - **Rule: a research heading is a container label, not another article title.** Its head (`.trash-research-head`) is a band on `--sidebar-surface` with a 1px `--strong-line` border, the research mark (`FlaskConical` on an accent tint), the title at 13.5px/600 clamped to two lines, and a summary line ("N sources · all deletable · removed 17 September 2026"). The rows below it are 13.5px/500 titles. Without that split a research question and a source title read as the same kind of thing.
  - The rows are one grid (`.trash-ledger`, subgrid rows), so the checkbox, title, version and state, removal date and actions line up down the whole research: sentence-case column heads with a select-all-shown checkbox, the title clamped to two lines, right-aligned facts, and the short removal date in tabular numerals. Restore and delete are quiet 32px icon buttons that appear on hover or focus and stay visible where there is no hover. At ≤760px the grid collapses to title, facts and date stacked, and the date carries its own label.
  - The version every row shares is a `.source-fact` dot with muted text; a rarer version and every state (cited with a tooltip, found again) keep the `.ref-pill` from the canonical tone map (§2.1). “Delete all permanently” stays inside the research's overflow menu.
  - A row's title opens the source sheet on the source's abstract, carrying that sheet's own removal notice and Restore action; a removed source's PDF opens only where this research cites it (D50), so a row with no stored abstract is plain text, not a link.
- **Settings.** A 760px centred column (styles in `Settings.css`): 20px/600 h1, a one-line lede, the Default models / Connections tabs, then sections headed by 14px/600 h2s. - **Connections.** Three-column tile grids (two at ≤760px): a tile is a hairline-bordered card with the name at 13.5px/500 on the left and the status pill at the top right (11px, no dot, radius 5, wraps rather than truncates; green when usable, neutral otherwise); the tile shows no logo (an exception to the connection-icon rule in §2.4, approved with the mockup port), with a soft shadow on hover and the accent tint when its sheet is open. ## 5. States and feedback

| State | Pattern |
| --- | --- |
| Loading | Short text ("Loading PDF text…") with `role=status`; a shimmer only for live model work |
| Live model work | `.shimmer-text` label, spinning step icon, or table run sweep; always with text |
| Empty | Plain muted sentence that names what is missing and, if possible, the next action. Rich empty states only where the empty screen is the start of a workflow (evidence table) |
| Attention / uncertain | Amber icon + text notice that says what to check |
| Blocking error | Red text with the cause and the recovery; `role=alert` |
| Not checked | Neutral fine print ("Semantic support not checked.") placed once per surface, never styled as success |
| Success | Toast that states what changed; green only for completed work |

**Rules:**

- Do not use a generic tinted box for every notice. An in-page notice is `<Notice tone="error" | "attention" | "info">` (`Notice.tsx`): a lucide icon plus text on the matching `--error-*`, `--warn-*`, or neutral tokens, with `role=alert` for errors.
- A disabled control always has a visible or accessible reason.

## 6. Motion

- Motion shows a state change or live work. It is never decoration.
- Durations:
  - ordinary feedback 100–200ms (toast 180ms, dialog 160ms, sheet 200ms);
  - live loops 1.6–2.2s (shimmer, pulse, sweep, ring);
  - jump flash to a target 1.6s.
- Ease out; no bounce or elastic motion; no animation that shifts layout.
- At most one live loop per region. Several live regions may animate at once only when each one reflects its own running work.
- **Rule:** every animation and transition, including smooth scrolling, has a reduced-motion path.
  - **Current:** a global `prefers-reduced-motion: reduce` block in `index.css` cuts every transition and animation to .01ms and one iteration and turns off smooth scroll-behavior.
  - Script-driven scrolls pass `behavior: scrollBehavior()` (`motion.ts`), which returns `auto` under reduced motion. Never hard-code `behavior: 'smooth'`.
  - The typewriter title shows the full text at once.

## 7. Responsive behavior

- The main breakpoint is **760px**: drawer sidebar, 46px top bar with menu, language and theme, smaller h1s, one-column source rows and activity, full-width report sheet with its toolbar actions as icons in the one head row, dialog actions stacked.
- Secondary breakpoints:

| Width | Change |
| --- | --- |
| 1180px | library panel stacks |
| 1050px | sidebar narrows to 224px |
| 720 / 650 / 640px | actions wrap, step notes lose their indent, PDF zoom hides, ghost columns hide |
| 600px | evidence grid narrows, rows stack |
| 520px | model palette becomes a bottom sheet |

- **Rules:**
  - Adapt hierarchy, not just size: metadata wraps, toolbars simplify, diagnostics collapse, and evidence access always stays.
  - Never truncate evidence-critical text (titles, passages, locators, failure reasons, version labels) without a way to reveal it.
  - Check every changed screen at desktop width and at 390px, in both themes.

## 8. Copy and language

- All UI strings go through `t(englishKey, vars)` in `i18n.ts`, with the Turkish map beside it. Label records live in `labels.ts`. Dates and numbers use `uiLocale()`.
- The tone is sentence case, plain, declarative, and provenance-aware. Controls name their action ("Use this value", "Go to cited text"). Toasts state the outcome.
- **Terms used consistently:** source, source version, passage, anchor/cited text, proposal, value, run, reading depth (abstract / full text), "semantic support not checked".
- Never write copy that implies verification DEIXIS did not do. "Located in the passage" is not "supports the claim".
- Provider and connection names come from `labels.ts`; model names use display names (§2.4).

## 9. Accessibility

- **Focus:** a 2px accent outline with a 4px offset on `.app` controls. Custom controls keep a visible `:focus-visible` state.
- **Semantics:**
  - Use base-ui Tabs, or `role=tablist/tab/tabpanel` with `aria-selected` and `aria-controls`.
  - `role=grid` for the evidence table, `aria-sort` for the library table.
  - Combobox/listbox with `aria-activedescendant` for quick find and the model palette.
  - `role=status` for live and loading text, `role=alert` for blocking errors.
- Decorative icons (including `ConnectionIcon`) are `aria-hidden`; the adjacent text carries the meaning. The typewriter title exposes its full text through `aria-label`.
- Do not rely on `title` alone to explain a disabled or icon-only control. Use an accessible label, and a Tooltip where sighted users also need it.
- Keep text contrast at 4.5:1 or better in both themes, on every surface the text can sit on (hover, selected, tint and side surfaces too), including amber text on tinted notices (`--warn-ink`).
- `--faint` is never used for text. An icon that carries meaning on its own needs 3:1 against its surface; `--faint` meets that on every surface in §2.1.

## 10. Known drift and exceptions

**Known drift:** none as of 2026-09-17.

**Deliberate exceptions:**

- Shadows on floating layers and scrims use literal black-alpha values (`rgb(24 31 45 / .22)` and similar) rather than tokens, because they are the same in both themes.
- The 3px citation gutter mark in the plain-text document (§2.3).
- The 2px neutral left hairline (`--strong-line`) on a quotation in the cell panel's evidence list (§4.8). It is grey, marks a quotation rather than a container, and follows the mockup's citation list.
- Open design item for the owner: `--attr-submitted` in the light theme is `#aa6c0d` (was `#c27a12`), because the old value gave 4.44:1 and 3.97:1 as text and 4.5:1 is required. It is now close to `--tone-uncertain` (`#b06d0f`), so the "submitted manuscript" pill and the OCR pill, which sit side by side in the source sheet and in a source row, look alike in the light theme. Both carry their meaning in text. Dark is unchanged. No colour was changed again; the owner decides whether the two should be told apart.
- The claim-candidate evidence sheet: a work found by a claim's prior-art search is not in the research corpus, so `PassageSheet` and its routes cannot open it. A listed work's title there opens a second, narrower sheet that shows only the exact text the model was given and the located quotes stored for it, with the same marking component. It is not a source-details surface (no PDF, no plain-text document) and says so.

## 11. Implementation guardrails

- Before styling, read the existing component and its CSS. Make the smallest reversible change and reuse existing classes and tokens.
- When a change leaves a CSS class with no reference in `apps/web/src`, remove its rules in the same change. Class modifiers built at runtime (`is-${…}`) count as referenced.
- Keep the stack: React 19, Tailwind 4, and shadcn/base-ui primitives in `components/ui`. Do not add a UI dependency for local styling or a single interaction.
- Use the same source metadata and provenance language across source rows, source details, the PDF view, the report, the evidence table, and exports.
- After a UI change:
  - run `npm run build` and `npm run lint`;
  - run the relevant Playwright acceptance tests;
  - look at the changed screen at desktop width and at 390px, in light and dark.
  - When the design depends on a changed API or validation contract, add a focused backend test.
- Do not land a change that breaks a rule in this guide. When a change needs a deliberate exception, record it in §10 with its reason.
