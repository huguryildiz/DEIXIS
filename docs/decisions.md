## D107 — Reverse citation search R3: a Home mode and a statement-check panel
Status: accepted · Date: 2026-10-18 · Writer: Claude (Opus subagent) · Reviewer: gpt-6.1-sol (round 1 not ready: one high finding, a slow read could show a stale check as current again, and four medium; round 2 hazır)
Context: R1 (D100) and R2 (D103) built the statement check without a screen. R3 of `.local/plans/reverse-citation-search-plan.md` adds it.
Decision: Home gets a fifth mode, "Check a statement": one sentence, at most 600 characters (one claim suggested when several sentences are pasted); with a search the discovery-end hook starts the check, with attached files only Home starts it. In the research view the panel stands where an answer would: the checked sentence of that revision, its revision and currency (the latest by `latest_check_id`; a stale one says why and offers "Check again", which sends a new request id and the expected scope revision, no model), model and cost, the work counts (candidates, listed, beyond the cap, left out, you excluded, no text) apart from the check counts (sent, completed, supports whole, supports part, not found, could not be checked, waiting), results grouped by result with the reading depth, each part as "Model: Stated/Not stated", and only backend-located quotes, which open Source details with those words marked. ## D106 — The reranker leaves chain-only records in their fused place
Status: accepted · Date: 2026-10-18 · Writer: Claude · Reviewer: Sol, 2 rounds
Context: In the 18 Oct benchmark (`docs/benchmark.md`) the reranker lowered recall@50 on the EE survey set from 0.129 to 0.091: it reads only title and abstract, and a survey's reference list holds many chained papers whose text looks far from the question. On BioASQ and LitSearch it helped.
Decision: Of the rerank window (the first N × pool factor fused records the person did not include), a record only citation chaining brought (`chain_heads`: a chained work the keyword pool does not hold) is not sent to the reranker and keeps its fused place; the other records are reordered by score among their own places. The step stores them as `kept_in_place`; a frozen list carries the field only when it is not empty, so lists frozen before D106 replay unchanged, and a kept record outside the window makes the stored rerank stale (`candidates_changed`). Offline check on the stored runs, same reranker scores, recall@50 with paired 95% intervals: EE test set 0.111 against 0.091 with the old rule, still below the fused order (−0.018, −0.025 to −0.011); LitSearch unchanged at 0.700, because chain-only records were 0% of its rerank windows. Keeping every record with any chain route out of the rerank brought EE to 0.125 but cost LitSearch −0.032 (−0.064 to −0.002) and was rejected.
Limit: BioASQ was not checked (its run data was deleted and its rows carry no routes). The check replays stored scores on one run per question; no new benchmark run was made, and half of the EE loss remains. The simulation called a record chain-only from its own version's routes, while the product decides by work (a published version chaining found, whose preprint a search found, stays in the keyword pool and is reranked), so the product may keep fewer records in place than the simulation did and the EE gain may be smaller (Sol); the run data needed to recount by work was deleted.

## D105 — Verify Citations after the V5 pilot: table rows, plain claims, three negation phrases and a freeze that waits for re-extraction
Status: accepted · Date: 2026-10-18 · Writer: Claude (Opus subagent) · Reviewer: Sol, 4 rounds; the last finding was fixed after round 4
Context: The V5 live pilot (`.local/verify-citations-v5-pilot/RESULT.md`, Sonnet 5.5 medium on the owner's LaTeX brief) sent 68 pairs and 31 ended `could_not_check`, all `invalid_model_output` after the repair: 17 Table 1 citations whose "sentence" was the whole `tabular` (10 failed the schema's part length, 7 coverage), 11 negation-window or cut-quote refusals, coverage failures with raw LaTeX in the parts (`\emph`, `~\tP`, `\section`, equations), and one part not found in the sentence. Separately, the first freeze went stale minutes later because the background arXiv-LaTeX equation reader re-extracted five cited PDFs. One positive error (P59) quoted the baselines a paper compares against as support for a claim about its method.
Decision: (1) Tables. A citation inside `tabular`, `tabular*`, `tabularx`, `tabulary` or `longtable` (in a `.tex` draft, or any draft whose marker is a `\cite`) is checked against its row only. The row is written as "Header: cell" pairs joined by "; ", header from the first row of the same tabular that has text (a missing header reads "Column n"; `\multicolumn` see Sol round 1 below): the first column's pair first, then every other column with a value in table order, then the columns whose cell is "no", in table order, so one claim part can hold all the crosses. A check mark (`\cmark`, `\checkmark`, `\ding{51}`, ✓, ✔) is the word "yes" and a cross (`\xmark`, `\ding{55}`, ✗, ✘) the word "no", in cells and captions alike. The table's caption (at most 600 characters, else its first sentence if that fits, else none) goes to the model as `citation_check_target.context`, a new optional StepInput field (at most 1,000 characters); no part copies or covers it. The marker's stored sentence span becomes the raw row, so the screen marks the marker in the row, not in the whole table. On the pilot's table the longest row claim is 160 characters. (2) Plain claims. Each marker now stores `claim` and `claim_context` (migration 0010): the sentence with markers cut and, for LaTeX, written as plain text by one fixed rule set in `draft_parse.plain_latex` (comments, `\label`, `\ref`-like and sectioning commands go with their arguments; text commands keep their text, `\textcolor` and `\href` their last argument; unknown argument-less commands such as `\tP` go; `~` a space, `--` –, `\%` %, accents composed; math keeps its source without delimiters or labels, Greek letters and common relations as Unicode, `\frac{a}{b}` as a/b, `\sqrt{x}` as √x, sizing commands gone, other commands as their name; inline math stays attached, `m$^{-1}$` is m^-1). The check, the passage ranking, the coverage and span checks and the cost estimate read `claim`; the raw `sentence` stays for the screen; the CSV and Markdown exports gain a `claim` column; a table row shows "Checked as the table row: …" under its sentence. A draft stored before 0010 has no claim and reads its sentence as before. (3) Negations. Three phrases are no negation, each only when all its tokens lie on the same side of the quote (read in two runs, before and after the span, so a quote starting at `only` of `not only`, or at `without` of `with and without`, is still refused): DEIXIS's own placeholder `[symbols not readable in the PDF]` (`documents/pdf.UNREADABLE`, the app's words, never the author's), `not` right before `only`, and `without` right after `with and` or `with or`. Every other rule stays as D99 left it, and every D99 regression test passes unchanged (`std.`, `does not\nsignificantly`, `5 mW` vs `5 mW/cm²`, `A/mW` vs `A/MW`, the 250/80 window, sentence ends crossed). Each refusal's repair message now says what and where: the negation word, its distance before or after the quote and the words around it; the negation the part or the quote holds alone; the character that touches the span; the passage's located words when the token sequence differs; and, when another quote of the same part was located, that removing the refused quote keeps the others. Per case, from the stored first and repair outputs: P09 (part "Order matters even without decay", quote with no negation): right, the part's "without decay" is a claim the quote does not state; kept, message names "without". P13 (quote starting after "entanglement-" in "entanglement-the time since…"): a false alarm on a dash the PDF wrote as a hyphen, but forgiving a hyphen before a word would let "significant" out of "non-significant"; kept, message names the "-". P40 (window holds "with and\nwithout the option of entanglement distillation" after "in a quantum switch having two clients"): false alarm, the phrase states both; loosened, the repair output now has no issue. P44 (quote "the cutoffs are not only state dependent" for a part without negation): false alarm, "not only" affirms; loosened, the repair output now has no issue. P46 ("there is no benefit to removing a qubit… hence we only consider polices that remove qubits at the time overflow occurs"): the "no" negates the clause before, not the quote, but it is a real negation in the window and the rule cannot tell clause scope; kept (D99's crossed-sentence rule). P47 and P48 (quote "there is no limit to the number of EPR pairs" and "a qubit never decoheres" for "unlimited memory and infinite qubit lifetime"): same meaning by a negated paraphrase; code cannot tell an equivalence from a reversal; kept, message names the quote's "no"/"never", and P47's message now says its other, located quote is kept if the refused one is removed. P49 (window holds "there is not bound…" and "there is no matching" from earlier sentences for one quote, and DEIXIS's placeholder for the other): the first kept (real negations, D99 window); the second a false alarm, loosened. P55 (part "rank requests… without age or fidelity", quotes with no negation): right, the quotes do not state the negated claim; kept. P65 (window holds the placeholder after "the fidelity of a Werner state at time t, F(t), is given by" and before "τ is a parameter…"): false alarm, loosened; its repair output still fails coverage on `\textbf{…}` and the equation, which (2) removes. P73 (window holds "does not require phase stability" from the sentence before, and "both with (turquoise) and without (blue) error detection"): kept; the second phrase has words between "with" and "without", which the narrow rule does not shield. So four cases held a false alarm that is now loosened (P40, P44, P65 and one of P49's two quotes), P13 was a false alarm kept for safety, and P09, P46, P47, P48, P55, P73 and P49's other quote were right or not safely separable. (4) Freeze and re-extraction. (a) A pair is stale when what the check uses would change: the entry's text unsettled, moved to another record or depth; a given passage no longer one a model step may read of the record (D46) or with another text hash; the depth label or the not-given count no longer true; or the revision's identity result about another file or extraction than the given passages (D96). A change elsewhere in the record keeps the plan, shows `text_changed_elsewhere` on the pair and in the preview, and is recorded in the check's basis. A plan frozen before fingerprints existed stays stale. (b) `POST …/plan` is refused with 409 `reextraction_pending` (and the entries) while the background equation reader is reading, or will still read by itself, a PDF an entry's text comes from (`equations.background_read_waiting`: a reader that can run, Marker, the arXiv source route or Mathpix, as `run_forever` reads it; a PDF with a successful extraction not yet read by Marker; state pending, reading, waiting for its source, or failed with attempts left). The view lists those entries as `reextraction_waiting`; the freeze step then says "Wait for re-extraction", offers no freeze and reads the view every five seconds. (5) The citation-check method text gains two paragraphs: a table row and its caption, and that a quote about the methods a work compares against (its baselines, or earlier work it describes) does not support a part about the work's own method, nor the other way round. No code rule for P59. `skill_package_hash` moved; the pinned hash test is updated.
Sol round 1 (fail-closed): each of Sol's three repros ended `found_whole`; now a pair that cannot be checked safely is never checked more loosely. (a) Math. Inline math becomes plain text only when it converts one way: ASCII letters and digits, `+ - = < > / * , . ( ) | ! '`, Greek letters and relations, math spacing, and sub- or superscripts of one token (`x^2`, `y_{i}`). Anything else (`\frac`, `\sqrt`, `\left`/`\right`, a grouped script of more than one token, any other command, display math and math environments) stays verbatim as `$…$` with its spaces collapsed, so `\frac{1}{2+3}` is no longer `1/2+3` and `x^{-12}` and `x^{-1}2` no longer share a text. The coverage and span checks read a `$…$` span as one token that a part must copy exactly. (b) Tables, replaced in Sol round 2 by a whitelist after three more holes (a `\multicolumn` behind a leading `\midrule`, a `\multirow` from the row above, a two-line header) each let a row lose a column and pass. A table citation is read only when its innermost tabular is simple: no `\multicolumn`, `\multirow`, `\cline`, `\cmidrule`, nested tabular or `\\[…]` split anywhere in its body and inside no other tabular; the header is exactly its first row and the next row starts with `\hline` or `\midrule` (a `\toprule` before the header is fine); the citation sits in a data row after that rule; and that row, leading rule and spacing commands stripped, has exactly as many cells as the header. Anything else makes the marker `unrecognized` with the reason `table_layout_not_read` (migration 0010 adds `parse_reason`): no claim, no pair, no model call, and the screen says the table layout was not read. The earlier spreading of a data `\multicolumn` over its headers is removed. Sol round 3 added two rules. Inside the tabular body only an explicit command allowlist may stand: the rules `\hline \midrule \toprule \bottomrule \addlinespace`, `\rowcolor`, the citation markers the parser found, `\shortstack`, `\textbf \textit \emph \textsc \texttt \underline`, the check-mark commands already mapped (`\cmark \xmark \checkmark \ding` and the rest), the escapes `\& \% \_ \# \$`, `\,`, `\\` and `\tabularnewline`, and inside math the Greek letters, relations, math spacing and a short list of standard math commands; the width and column spec allow only `\extracolsep \fill \linewidth \textwidth \columnwidth`. Any other command, a user macro above all (one defined as `\multirow` or as `A & B` could hide a row or a cell), refuses the whole table. And comments are stripped once, before any marker or table is read: a `%` starts a comment when an even number of backslashes stands before it, so `\\%` is a line break and then a comment while `\%` and `\\\%` stay literal; a `\cite` inside a comment never becomes a marker. In a draft that is not `.tex`, where comments are not stripped, a comment `%` inside a tabular refuses the table. Sol round 4: a command name is read whole with `@` (`\textbf@pair`, `\@foo` and `\emph@x` are names off the allowlist, in the body, the spec and math alike), a `\cite@x` is no citation marker, and inside a marker only its cite command is let through, so a command in a marker's note is checked like any other; a star or digit after an allowed name is a separate token and reads no other macro. The pilot's Table 1 passes all of it: its 16 table markers are still read as rows, and no command had to be added for it. (c) Placeholder. A quote that overlaps the PDF reader's placeholder, even in part, is refused (`placeholder`); the placeholder's negation shield applies only when the whole placeholder lies outside the quote. The screen now always shows the checked claim under the raw sentence, and while a re-extraction waits it shows the next try time when the state has one.
Pilot re-run (18 Oct, `b0817990`, `.local/verify-citations-v5-pilot/RESULT-r2.md`, same frozen labels, no human labels: readers Sol and an Opus subagent): 68 pairs sent, 1 `found_whole`, 45 `found_partial`, 13 `not_found_in_given`, 9 `could_not_check` (all `quote_meaning_differs`, negation or an adjacent sign); on the 30-pair sample `could_not_check` 4/29 = 13.8% (≤20%), 0 positive errors by both readers, calls and tokens inside the preview ranges, so all three thresholds pass. One run only, and pairs whose code path did not change also moved, so part of the gain may be run-to-run variation. Open: a table row's name column ("Work: authors") is treated as a claim part, so quoting the author names gave `found_partial` on an all-cross row (P25, outside the sample). The freeze's `reextraction_pending` path was not exercised live.
Limits: Model-free tests only (`tests/citation_check/test_citation_check_pilot.py`: the pilot's table and LaTeX sentences and the passage excerpts of the 11 refusals, copied from the owner's draft and the pilot's given passages, not SYNTHETIC; the workflow cases SYNTHETIC) and the verify-citations Playwright spec, whose re-extraction step changes the view's answer in the browser because the fixture server has no equation reader. No model was run: whether a model now completes table rows, plain claims or the reworded repairs is unmeasured, and the pilot is not re-run. Re-scoring the pilot's stored answers with the new code clears only the two repair outputs whose sentence did not change (P40, P44); the others were written against the old LaTeX sentences and cannot be re-scored. (4a) helps less than it reads: passages are immutable and a re-extraction writes new passage rows, so a re-extraction of a cited PDF always makes its pairs stale through their given passages (D46 forbids sending a superseded extraction); in the pilot all 12 stale pairs had every given passage replaced and 9 had a changed passage count. (4b) is what prevents the pilot's failure. A re-extraction that starts after a freeze (a new PDF arriving later, a person's retry) still makes the plan stale and the check refuses; the check does not wait for it. A failed equation read with attempts left blocks the freeze until its retries end (up to three, ten minutes apart). The plain-text rules cover common LaTeX only: a person's macro with arguments keeps its argument text (`\tagbox{teal}{P}` would read "teal P"), `\{` outside math reads as a brace, and a math rendering such as `e^-(a+b)τ/T_2` is a reading aid, not a typeset formula. A sentence that is a table caption keeps its caption text; a footnote's text stays in its sentence. The baseline rule lives only in `citation-check.md`; `statement-check.md` (reverse citation search) does not have it. The coverage rule still counts every word of a multi-citation sentence (P54, P64 and P71 declared `covers_whole_sentence` false); that is unchanged. No Turkish copy was read by a native reader.

## D103 — Reverse citation search R2: how a statement check starts, resumes and goes stale
Status: accepted · Date: 2026-10-18 · Writer: Claude (Opus subagent) · Reviewer: gpt-6.1-sol (round 1 not ready: one high finding, a removed work's result stayed current, and two medium (optional expected revision, a zero cost shown before an attached PDF finished); round 2 hazır)
Context: R1 (D100) built the statement check with only a private constructor. R2 of the plan (`.local/plans/reverse-citation-search-plan.md`) adds the ways it starts, resumes and goes stale; the screen is R3.
Decision: `statement_check.request()` opens a revision: the model comes from the request, else the literature model in Settings at that moment, and is stored before any pricing, so later Settings changes reach neither the price nor the run; a repeated request id in the same research returns its revision, in another research it is `request_conflict`; it is refused with `no_model`, `not_statement`, `revision_mismatch`, `discovery_mismatch`, `cutoff_missing` or `run_active`, the last two checks in the creating transaction. A recheck is a new request id and a new revision; resume continues the same revision through the run resume path. `POST /api/researches/{id}/runs` accepts `statement_check` (the Idempotency-Key is the request id, `expected_scope_revision` is required, a refusal is 409 `{code, detail}`) with its own budget, planned works × (1 call + 1 repair); other kinds may not name a model. `fast_path.with_intent` freezes the `statement` intent into the discovery budget; at discovery end `after_discovery` requests the check instead of an auto answer under the key `statement_check:auto:<research>:<question revision>:<cutoff step>` inside a savepoint, and a refusal (such as no model in Settings) records `statement_check_skipped` with its reason and starts nothing. In attached scope there is no discovery: the run pauses with `attachments_extracting` while a current file is still `pending`, then freezes the list from the attached files with a snapshot (asset, extraction version, text hash); a failed extraction is `no_text`; the freeze is one guarded write shared with the preview, and a waiting preview shows the cost as unknown, never zero. `refresh_currency` marks a revision `stale` (never rewritten) for `question_changed`, `person_choice_changed`, `source_changed` or `source_removed`; it runs before each result is stored and when the list, view or export is read. The list and view name `latest_check_id` and `is_latest` (highest revision); an older revision stays current while its inputs hold. Under the statement intent the criterion, query, abstract-screening and full-text prompts get a note that the question is a claim and relevance is its topic, not agreement with it (SKILL.md; `skill_package_hash` moved). New read routes list, view, preview and export a check; `api.startStatementCheck` requires the expected revision; `intent` accepts `statement`, and a statement question over 600 characters is 422.
Limits: Model-free tests only; no real model or real search has run a statement check. No Home mode or panel yet (R3); live support pilot R4; "challenges" R5. Whether the claim note keeps screening on topic is not measured. An attached-scope cost is unknown until its files are extracted.

## D102 — A reranked record past 20,000 characters is cut and counted, not refused
Status: accepted · Date: 2026-10-18 · Writer: Claude · Owner choice: cut and record
Context: The first benchmark question with the owner's settings (BioASQ trial, Voyage rerank-3-lite, 200 candidates) failed its rerank with `reranker_failed`: one candidate's OpenAlex "abstract" held the whole article (23,753 characters), past DEIXIS's own `MAX_DOCUMENT_CHARS` (20,000, set with D88/D89, not measured; Voyage itself allows 32,000 tokens per query and document). Limits: A cut record is scored on its title and opening only. Cohere's per-document token check (4,096) still refuses the whole request when a record passes it. How often this happened in earlier runs is not counted.

## D101 — Verify Citations V4: the screen, a Library tool that shows each stored count, status and result apart
Status: accepted · Date: 2026-10-18 · Writer: Claude (Opus subagent) · Reviewer: gpt-6.1-sol (round 1 "ready with fixes": three high findings and three backlog items, fixed as below: the quote mark is tied to the opened passage and its located words, with comparison signs kept wherever the page is searched; "What was read" names only what was given and each quote says where it came from; the draft list counts completed and could-not-be-checked pairs apart; a stale plan has a "Freeze the plan again" control; a check found running is polled with progress over one basis; the two file buttons have their own names and Source details its own labels)
Context: V4 of 5 of Verify Citations (plan in `.local/plans/verify-citations-plan.md`; V1 D86, V2 D96, V3 D99). The routes existed; there was no screen. No real model was run for this slice.
Decision: A "Verify citations" button in the Library head (and on the empty Library) opens its own page, `#/library/verify` (decision 3: no question, no discovery). There a person pastes a draft or uploads `.md`, `.tex`, `.docx` or `.txt`, with an optional BibTeX or RIS file, and earlier drafts are listed (new `GET /api/citation-checks`). A draft page shows the counters in three groups (draft, cited works, pairs), each count on its own and `–` for one not started, never 0; one next-step box walks look up → get the text → freeze → preview → start; the citations table; the bibliography with each entry's link, text and flags and "Attach my PDF". The preview names the model from Settings, the pairs in draft order, the pairs beyond the cap, passages per pair, model calls and the cost range; a cost the API calls unknown reads "Unknown" with its reason, and with no model Start is disabled with a visible reason. Start sends the previewed revision and the previewed model; the 409 codes (`plan_stale`, `plan_not_previewed`, `model_not_previewed`, `no_model`, `plan_revision_mismatch`, …) get their own sentence and a refused preview is read again. While `/check` runs the view is polled each second for a progress bar; a paused or failed run says why (`pauseReasonText`) and continues with the run's own model. The table has one row group per citation occurrence and one row per cited work; columns are the sentence with the marker marked, the work from the stored record (never the draft), what was given, the same before and after the check and never the result ("Full text · 5 of 5 passages given", "Abstract only", "6 of 40 passages given"), the result as a tinted pill with each located quote and its origin ("Quote from the abstract", "Quote from the PDF text") under it and the status as plain text with an icon, so a status never reads as a finding. Unread markers, ambiguous and unresolved pairs carry a reason built from the stored style and status (the parser keeps no reason). A located quote opens `PassageSheet` on its passage alone (`passageOnly`: the page's whole text is not searched again) with the backend's `anchor_text` as the only highlight, found in that passage's own text as written; the PDF view marks nothing. Where the plain-text document view still searches a page for an answer's anchors (`pdfDocument.locateAnchors`), comparison signs (`< > = ≤ ≥ ≠ ±`) now count in the match, each as a token of its own, so `x < 5` never marks an earlier `x > 5` and the anchor `0.05 the outcome changes` in `p=0.05 the outcome changes` is marked from `0.05`, never widened to `p=` (`e2e/pdf-document.spec.ts`). The earlier-checks list shows completed and could-not-be-checked pairs apart. CSV and Markdown are the existing export routes. Backend: the middleware that hides the internal research now lets `GET /api/researches/{id}/passages/…` and `/assets/…` through for it, so Source details can read the passage and its file; those routes still check membership, and every other route of the internal research stays 404 (test). ## D3 — Up to five seed PDFs, uploads and Zotero through one gate (seed_pdf_v2)
Status: accepted (owner 11 Oct 2026: "PDF veya PDF'ler seed olarak verilirse sorun olmasın, Zotero entegrasyonu da aynı şekilde çalışsın") · Date: 2026-10-11 · Writer: Claude · Reviewer: gpt-6.1-sol medium (plan 3 rounds, code 2 rounds)
Context: D2 let one PDF guide the search. With several PDFs, Home made the user pick one with a radio button. A research started from a Zotero collection alone chose no seed and did not start its search. A Zotero record's own DOI was not used, so a PDF with a blank cover page never matched.
Decision:
- The seed is an ordered set of at most five PDFs (`seed_snapshot_json` version 2, with a `seed_key` fingerprint). Uploaded files and Zotero or library PDFs go through the same function (`store.set_seeds`), and one function decides which sources can be seeds (`store.seed_candidates`); the page lists exactly those. Order is the request's order, or the candidate order for `all_eligible`. With more than five eligible PDFs, the five whose first two pages share the most question words are taken; the rest are listed as `not_selected`. The old single-seed format is read as a one-element set without rebuilding its excerpt.
- The excerpt budget is split across seeds: one seed keeps D2's excerpt exactly; with n seeds each gets `max(1, 4 // n)` passages and `5600 // n` characters. The passage cap becomes `max(4, n)`, so five seeds give five passages; the 5,600-character cap stands.
- Matching keeps D2's rules per seed, with one DOI request for all seeds and one meaning search for each undecided seed (at most 1 + 5 requests). The DOI request asks for up to 100 works and counts as failed when OpenAlex reports more matches than it returned, so two works sharing a DOI are never cut to one; for a single uploaded seed this is the only change from D2's requests (`per_page=100` instead of the DOI count). A Zotero or library seed may also match by its record DOI (`record_doi`): exactly one OpenAlex work with that DOI, whose title equals the record's title and stands in the first 1,500 characters of the first page that has text (page 1, or page 2 when page 1 is blank). A citation on page 2 of a page-1-text PDF never counts. The result of that check is kept as `record_check`.
- Matched seeds are the first chain seeds in seed order, deduplicated by OpenAlex work, within the policy's seed count. The semantic query is the question followed by equal shares of each seed's text within 1,500 characters, the longest `search.semantic` OpenAlex accepts (one seed: D2's string, cut at 1,500); the parts that went in are kept as `seed_parts`. D2 assumed 2,000 from the help page; the live API refuses more than 1,500 with HTTP 400, which a live run on 11 Oct showed on every seeded run until this was fixed, and also failed the seed lookup's meaning search. A run whose seed lookup failed does not pass that failure to the next run of the revision. The query writer sees every seed's excerpt. The ranking reads each seed through its frozen context.
- A run that opened the D2 seed step, or froze a D2 protocol, finishes under D2; no finished lookup is sent again.
- The research page shows one line per seed: what OpenAlex matched, and which of query writing, the similar-paper search and the citation chain actually used it, read from stored steps (a chain request counts only when it was sent). Home makes every added PDF a seed and starts the search, also when only a Zotero collection was added. Repeating an identical seed request changes nothing and returns 200; a 409 is a real conflict and Home then does not start the search.
Limits: Live check (11 Oct, gpt-5.6-luna, Standard, one run per arm, rule frozen beforehand in `.local/seed-live-2026-10-11/RULE.md`): 3 questions × none / 1 seed / 2–3 seeds, the seeds being target papers (a leaky test). All 10 seed PDFs that matched went to the right OpenAlex work (9 of 10 matched, none wrong). Share of the remaining targets in the top 50: 1 seed 0.55 vs 0.46 without; 2–3 seeds 0.42 vs 0.44, falling on uwsn_kconn2022 (2/12 vs 5/12) and battery_soh (1/12 vs 3/12) and rising on dbr_vbf. The frozen rule's verdict is "help not shown" (one 3-seed run was 86 s slower than the 60 s allowance). Single runs; the drops may be noise. Tests use SYNTHETIC records and a scripted OpenAlex and Zotero. With five seeds the query writer sees about 1,100 characters of each first page. The top-five choice for a large collection uses question-word overlap only; the user can change it on the research page. The quick chain budget may not cover every seed's reference list. `search-query.md` changed, so `skill_package_hash` and protocol hashes change for every run.

## D2 — The seed PDF guides the search (seed_pdf_v1)
Status: accepted (owner 11 Oct 2026: "planı yaz ve Sol'a inceletip kodla") · Date: 2026-10-11 · Writer: Claude · Reviewer: gpt-6.1-sol medium (plan 3 rounds, code 2 rounds)
Context: In a "Files + academic search" research the UI always picks a seed PDF and said its passages "guided the search", but no search step read them. The semantic query was the question alone, the chain seeds were the top semantic results, and the ranking saw the upload with a file-name title, no abstract and no references.
Decision:
- Before anything else plans, a discovery run with a ready seed looks the PDF up in OpenAlex (`workflow/seed_match.py`, step `seed_match`): the DOIs on physical pages 1–2 in one `filter=doi:` request, then, only if no DOI record decides, one semantic request with the head of page 1. A work is taken only when its title (4+ words) stands in the first 1,500 characters of page 1 and exactly one work does; two or more is `no_match`. A DOI alone never decides. Each lookup is its own step, so a resumed run does not send it again; a failed lookup is recorded (`lookup_failed`) and the run goes on.
- The protocol freezes the full context (`seed_match`: status, identifiers, title, abstract, reference list, the first 2,000 characters of page 1). The chain, the semantic query and the ranking read it only from the protocol. A run whose protocol froze before this rule finishes without it.
- Matched: the PDF is chain seed 0 (it takes one of the policy's seed places; the request caps are unchanged), and the same OpenAlex work is never chosen again. The ranking reads the PDF seed with the matched title, abstract, references and OpenAlex identity, and never scores the PDF against its own OpenAlex copy or takes that copy as a second seed.
- The OpenAlex semantic query is the question followed by the matched title and abstract, or the PDF's first page when unmatched, cut at 2,000 characters; the ranking's embedding query stays the question.
- The query-writing model (`search_query`) receives the frozen seed excerpt as passages; `search-query.md` tells it to take field terms from it but let the question decide. A query another run wrote without the same seed pages is not reused.
- The research page says what the seed did, from the protocol (`scope.seed_use`).
Limits: How often the matcher picks the right work, and whether seeding raises the targets in the top 20, were not measured; all tests use SYNTHETIC records and a scripted OpenAlex. PDFs with a cover page match nothing (fail closed). An unseeded run is unchanged except for `skill_package_hash` (and so the protocol hash), because `search-query.md` changed. Backlog from review: the page sentence uses the past tense once the protocol freezes, before the chain has run, and says "query writing" even when `DEIXIS_SEARCH_QUERY=code`; the transcript does not count the PDF seed apart; no Playwright case for the seeded path.

## D1 — Baseline (10 Eki 2026)
Status: accepted (owner decision 10 Oct 2026: clean start, today's fast path is the baseline) · Date: 2026-10-10 · Writer: Claude
Context: The owner chose a clean start. The fast path (old D250 to D260) became the only search path, and the old search rounds, the second-round term expansion, the old citation chain, the old answer assembly, the interactive term approval and all support for libraries written by earlier versions were deleted (commits 5a30689 to 8637fa3). The migrations were squashed into one baseline (old D261). This entry records what the code does now, so that later entries have one starting point.
Decision:

Architecture
- A FastAPI backend (`backend/deixis`) serves a React UI (`apps/web`) on loopback only. The API checks Host and Origin against an allowlist, and every mutation needs the double-submit CSRF token (`deixis_csrf` cookie, `x-deixis-csrf` header).
- A research has scope revisions. Each run is a list of steps keyed by `operation_key`. A step that already succeeded returns its stored output, so pause, resume and crash recovery never repeat a model call or a provider request that finished.
- A run stops at its next checkpoint on pause, cancel or a newer scope revision.
- One worker owns execution through an OS advisory lock (`flock`). At startup it marks half-finished steps and model sessions `outcome_unknown` and the runs that held them `paused`; it does not retry them on its own. The user resumes.

Model boundary
- Each model step gets a stored `StepInput` (records, allowlisted IDs, `step_input_id`, `scope_revision`, `skill_package_hash`) and a strict JSON output schema. Everything sent is stored before the call.
- The model has no tools. A tool item in the output fails the step with `model_isolation_violation`.
- Output from a model other than the requested one is recorded and never used (`model_mismatch`). No other model or connection is tried in its place.
- Schema repair is bounded: one repair call (`MAX_SCHEMA_REPAIRS = 1`), none for `vocabulary_labels` and `abstract_screening`. The answer step has one exception: when only the several-sources rule for a `source_stated` claim (and anchor defects code may salvage) still fails after that repair, it makes one more call, `grounded_answer_resplit` (old D249), if the model-call budget still allows it. If repair fails, the answer is stored as an unverified draft and is not shown as a cited answer.
- Answer and review steps see short citation handles instead of record IDs (old D12). Code resolves them back to record IDs before validation.
- Editing a runtime file of `methods/deixis-research/` changes `skill_package_hash`. The app refuses to start when the package fails its integrity check.

Evidence rules
- Every published claim cites passages that were given to that model step, and each claim-passage link needs a contiguous anchor that code locates in the stored passage text. The UI highlights only that located anchor.
- A `source_stated` claim cites one source; two versions of one work count as two sources and are not independent evidence. When more than half of at least four claims are `analyst_inference`, the answer step makes one optional rewrite call.
- `structurally_valid` means the answer passed these deterministic checks. It does not mean each cited passage supports its claim. The `answer_review` run is a separate recorded model assessment and never edits the answer.
- Reading depth stays visible: metadata, abstract, selected PDF passages and full text are different evidence levels. Abstract screening never includes a source by itself, and a user's own inclusion or exclusion overrides the model's.

Fast-path policy (`fast_path.py`, `fast_path_v1`)
- Every new discovery run freezes this policy into its budget, with a `policy_hash`. Later code changes do not rewrite a frozen policy.
- The numbers per depth, from `fast_path.MODES` (stage seconds for plan, search, ranking, read and answer):
  - Quick: 30/30/30/60/30 (180 s); N 25, K 10; keyword record cap 450; 10 chain seeds, 2 backward and 2 forward chain requests.
  - Standard: 30/45/60/120/45 (300 s); N 50, K 20; cap 1000; 20 seeds, 4 backward, 8 forward.
  - Detailed (policy mode `deep`): 45/90/120/270/75 (600 s); N 100, K 40; cap 2000, of which 500 are reserved for Semantic Scholar; 30 seeds, 8 backward, 16 forward.
- N is how many works of the frozen list are screened and looked up; K is how many of them can reach full text.
- Stage time is active wall time that survives pauses and restarts. Unused time carries to the next stage, overrun is recorded as debt, and each stage keeps at least 25% of its base.
- Search, ranking, read and answer have soft deadlines. Submitted model calls drain; a read-stage call still out 5 s after the deadline is cut (`model_read_cutoff`).
- Plan:
  - code takes search words from the question, three optional `vocabulary_labels` calls sort them into blocks, and OpenAlex count requests check the terms;
  - a `search_query` model call writes the query blocks (`DEIXIS_SEARCH_QUERY=model` by default); if it fails, the run stops with `search_query_failed`;
  - at most one OpenAlex request routes the sources (none when no domain source needs it);
  - three optional `criterion_proposal` calls vote the inclusion criterion;
  - the approval is recorded as `unattended`, and nobody is asked.
- The protocol, with its search plan, freezes after these planning requests and before the first request that fetches search results.
- An empty vocabulary (`vocabulary_empty`) or a too-broad one (`vocabulary_too_broad`) ends the run with that message. There is no approval card; the user rewrites the question, which makes a new scope revision.
- Search: one OpenAlex semantic page (up to 50 records) and OpenAlex keyword pages of 100, read page by page across queries under the keyword cap. Detailed also sends one Semantic Scholar bulk query. No other provider is searched and there is no second search round.
- Chain: one round, OpenAlex only (backward references and the first cited-by page per seed), overlapping the search and cut off before the ranking deadline.
- Ranking embeds the pool and freezes the list.
- Read: Semantic Scholar and Crossref look up missing abstracts for the top N; when Scopus is in scope, configured, its institutional COMPLETE view is confirmed (`complete_view_entitled`) and the lookup budget allows, it completes the abstracts still missing. Each batch of abstracts is screened by two model calls. At most K works get full text; a slot whose work found no text passes to the next work in list order.
- PDF retrieval uses 12 shared slots. At the read cutoff, fetches already running are handed to the background lane and go on; queued works start from the background queue only while fewer than 4 background fetches run.
- When discovery completes, one answer run starts on its own. It answers from the evidence the read stage owned at its cutoff, then queues a separate `answer_review` run.
- Late full text can produce one new answer revision (`max_revisions: 1`). The first answer stays as it was.
- An answer over attached PDFs only (no completed discovery) uses the inspection route: PDF fetch, lexical and semantic passage ranking, then `grounded_answer`.

Providers
- All connectors in `providers/registry.py` stay: OpenAlex, Semantic Scholar, Crossref (lookup only), arXiv, bioRxiv (through OpenAlex), PubMed, IEEE Xplore, Scopus, CORE, SerpApi (supplementary), plus the Zotero collection import. Keys come from the untracked `.env` or the system keychain.
- The research search uses only OpenAlex and Semantic Scholar. Abstract lookups use Semantic Scholar and Crossref, then Scopus under the conditions above. The other connectors stay registered and configurable.

Storage
- One SQLite connection is shared by the API and the worker on the event-loop thread. Writes are short synchronous transactions with no `await` inside, and a UI-visible event is written in the same transaction as the state it describes.
- The schema starts from `storage/migrations/0001_schema.sql` (D75; it replaced `0001_baseline.sql` and 0002–0022). A schema change is a new numbered file from `0002_` on. A migration that has been applied is never edited, the baseline included, and tables are not dropped.
- Runtime data (database, PDFs, provider payloads, Codex home) lives in `DEIXIS_DATA_DIR`, never in the repository.

One-time reset (old D261)
- The 77 old migrations were squashed once into the baseline, and the code that kept earlier libraries working was removed. A library written before the reset is refused at startup, and its app data folder is to be deleted. This reset is not repeated. (D75 squashed again, but kept libraries from before it working.)

Limits:
- This entry restates decisions made, reviewed and tested under their old numbers and adds no behavior. The commit that wrote it also removed two method files no step loaded and corrected method and project docs to match the code.
- The tests run on synthetic records and a scripted model. They show workflow behavior, not answer quality or live latency. Live measurements are in STATUS.md and the old log.
- The anchor locator accepts a near match at a provisional 0.9 ratio over one contiguous region.
- Stage deadlines are soft, so a run can exceed its target time.
- The startup refusal of an old library says "newer DEIXIS", which is misleading for an older library (old D261).
