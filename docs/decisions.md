## D99 — Verify Citations V3: a model step per planned pair, and the code decides the result (2026-10-18)
Decision: Each planned (citation, cited work) pair goes to a model step with a strict schema, and the code decides the result (`found_whole`, `found_partial`, `not_found_in_given`) from quotes it locates itself, each only in the passage it names. Many structural checks (quote location, number, unit and negation rules) send an answer to one repair, and a still-invalid one is `could_not_check`. `/check` runs only a revision previewed with the model named and never re-freezes or reads another plan; before each send it fails the run if the method package changed or the pair's plan went stale, a step that already succeeded is read back and never sent again, and a provider failure or a stop leaves the pair `planned`, never `could_not_check`.
Why: V2 froze which passages each pair is given, and V3 turns a model's answer into a result without trusting the model's own claims.
Limit: Model-free tests only: no real model has read the method text and nothing measures the false positive rate. The rules are structural screens meant to miss positives rather than accept wrong ones, so a paraphrase that reverses a claim without these tokens passes, many valid quotes are refused, and Turkish verb negation is not read.

## D90 — Built-in models run on llama.cpp from a pinned GGUF catalog (2026-10-17)
Decision: DEIXIS downloads llama.cpp build b11711 and a catalog of eight GGUF files, each pinned by revision, size and sha256 and each downloaded, checked, removed and chosen on its own. Each chosen model runs in its own `llama-server` on a loopback port with a per-process key, ready only after an authenticated probe, killed with DEIXIS by a watcher and stopped after 300 s idle; a vector that is null, not finite, of the wrong dimension or not unit length is refused.
