# Isolated quantum search: 500 initial slots, conditional 1000 ceiling

**Status:** prospective development protocol and executable trial profile; no new search result is claimed here. This profile does not change the DEIXIS product default. The earlier quantum/Elicit examples informed its design, so this question is not an independent holdout.

## Question and scope

> Which mathematical optimization models have been proposed for end-to-end entanglement distribution in quantum networks? Compare their decision variables, objectives, constraints, and treatment of routing, scheduling, memory capacity, fidelity, and decoherence. For each model feature, cite the supporting paper and state whether it was verified from the abstract or full text.

The trial discovers *candidates*. Its automated choices have `machine_provisional` status because the user elected to omit seed and term approval for this experiment. No record is human-included, and no model feature is full-text verified merely because a PDF was downloaded or extracted. The known six DOIs and Elicit's nine included papers may be consulted only **after** the discovery ledger is frozen.

## Six stages and frozen budgets

1. **Question decomposition.** A selected Gemini text model proposes exactly one `core` and four distinct `mechanism`, `method`, `outcome`, or `context` concepts with English scholarly synonyms. The existing DEIXIS **full-phrase legacy compiler** creates one core-only and four paired OpenAlex title-and-abstract queries. `prepare` saves the model output, resolved model, compiled strings, compiler version, and protocol hash. The operator inspects this frozen plan before `run`; the run never regenerates queries from live results. Invalid, duplicate, or semantically underspecified queries stop preparation before provider requests. No model/provider substitution is allowed.
2. **Initial search and identity ledger.** OpenAlex receives five queries, page 1, `per_page=100`: **500 returned-result slots**, not a promise of 500 unique papers. Each request, retry, HTTP state, provider-reported total, returned row, exact DOI, OpenAlex ID, and route is saved. Exact DOI groups are merged; DOI-less rows retain their OpenAlex identity. Separate identities with the same normalized title are flagged for later inspection, never silently deleted. The second page of these *same five queries* is sent only if all five first pages complete, at least three return 100 rows, and at least 50 of their combined last-25 rows are previously unseen identities with a title and abstract. This deterministic operational gate measures whether depth is still yielding screenable novelty; it is **not** a relevance test. Page 2 adds at most 500 more slots, so initial text search cannot exceed **1000 returned slots or ten page requests**. A failed first page blocks expansion and remains a failure, never zero results. No third page. Failed page-2 calls produce a partial run. The 100-result page size follows [OpenAlex paging guidance](https://help.openalex.org/api/paging/).
3. **Seed ranking.** Gemini `gemini-embedding-2` encodes the question and unique title/abstract records. A title-domain gate followed by question cosine and diversity ranking chooses at most three OpenAlex seeds. Record scores, model, chosen IDs, and machine-provisional status. Embedding failure ends graph expansion; citation count or semantic distance alone never certifies relevance. After ranking, select at most 20 records with provider-stated source version and DOI for the PDF queue, without using Elicit/control labels.
4. **Citation graph.** For each of at most three seeds, preserve all OpenAlex reference IDs, hydrate at most 100 (shared by more seeds first, then ID order), and request one first page of up to 25 forward citations with the verified `sort=cited_by_count:desc` syntax. Log unhydrated reference IDs and each directed edge. A conditional second ring selects up to two *new* first-ring, title/abstract-screenable, machine-provisional records whose question score exceeds the weakest initial seed, only when all first-ring calls completed; it applies the same per-seed caps. Thus at most 10 graph API calls, 500 hydrated reference slots and 125 forward slots, plus unhydrated ID edges. A missing abstract, unavailable endpoint, or 429 is incomplete evidence. No third ring or adaptive budget increase.
5. **Controlled term feedback.** A selected Gemini text model proposes at most ten short technical phrases from the top ten provisionally relevant first-ring abstracts. Code accepts at most two only if each exact normalized phrase occurs in at least two different provisional-positive abstracts, is absent from the initial sent query strings, and compiles into a provider-valid query. One OpenAlex feedback query may return at most 100 rows. Save proposing records, phrase counts, rejected terms, actual query, and overlapping discovery routes. If the model fails or no term passes, skip with a reason; do not silently send a hand-written replacement.
6. **Parallel PDF and reporting.** After initial ranking, start the existing isolated PDF prefetch task while graph and feedback continue. At most 20 DOI/version-labelled works, five lookup routes and two downloads per work, two simultaneous jobs; validated PDF bytes get page text first, and optional Marker can enrich math/table pages. PDF lookup failures, available files, readable text, Marker output, and *actually inspected* full texts have separate counters. The final ledger has a PRISMA-S 16-item manifest, request/query dates and limits, graph seeds/rounds, all identified routes, count reconciliation, and explicit `incomplete` entries. PRISMA-S documents the search; it does not itself determine relevance. Do not draw a completed PRISMA 2020 flow or claim an included-study count without human screening and full-text decisions.

The text-slot budget excludes graph, feedback, PDF, Gemini, and retries. Count **attempted and delivered requests** separately for every route. The runner creates a new ignored `.local` output directory, never opens the DEIXIS library, and never uses port 8765. A network or model failure leaves partial evidence; rerun into a new directory rather than editing a prior ledger.

This first profile uses **OpenAlex only** for the fixed 500→1000 text budget and graph. Semantic Scholar's keyed first-page search worked in an earlier diagnostic, but a paced citation request still received 429; its condition remains unresolved. A future separately budgeted multi-provider arm can add it after that diagnosis. A missing Semantic Scholar branch is recorded as *not attempted*, never as zero results or proof of absence. This limitation affects coverage and any comparison with Elicit.

## Evaluation gate after execution

Freeze the run before loading the control DOI and Elicit CSV files. Report exact DOI and inspected version-group overlap as descriptive comparisons, with first-discovery route and PDF/reading depth. Then compare against equal-budget additional text pages/queries and human relevance labels on new questions before proposing a product default. The six known DOIs are development controls, not a field-recall denominator. Elicit's included list is not its complete retrieved candidate pool; overlap with it is not a recall estimate. No feature-level model comparison is publishable until the supporting source passages are actually inspected and labelled abstract versus full text.

## Operational commands

`prepare` and `run` are separate to keep the query plan frozen. Both require explicit, unused output paths; credentials are read from the environment or an explicitly supplied local `.env` file and are never written to ledgers.

```sh
uv run python scripts/isolated_hybrid_search.py prepare --model MODEL_ID --plan-dir .local/quantum-500-plan
uv run python scripts/isolated_hybrid_search.py run --plan .local/quantum-500-plan/plan.json --output-dir .local/quantum-500-run
```

The exact `MODEL_ID`, reasoning effort, plan hash, script hash, and actual request/response dates belong in the run record. The trial runner and this protocol are proposals until those commands succeed; a completed execution still remains a machine-provisional search, not a systematic review.
