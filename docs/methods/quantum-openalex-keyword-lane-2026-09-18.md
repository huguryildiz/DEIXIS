# Isolated OpenAlex-assigned keyword inheritance lane

**Status:** separate post-hoc development experiment. The source-owned IEEE author-keyword lane stopped before search because its three DOI responses had no `author_terms`. This lane explicitly uses **OpenAlex-assigned** work keywords instead; it is a different metadata source and cannot be described as inheriting author keywords. OpenAlex documents that its work keywords are selected from assigned topics and scored against title/abstract embeddings, with up to five per work. They are model-derived descriptors, not text verified in a paper.

Select the same three highest-cited, non-survey, title-filtered records from the frozen C pool used in the earlier cited-paper round. Freeze the identities and citation-count snapshot before metadata lookup. Request each work by its OpenAlex ID once, recording response status and keyword objects with scores. Require exact OpenAlex ID matches. Keep the first three returned keywords per work, exclude generic reporting labels and exact terms already used in B/C, and require a keyword to contain a question-domain token (`quantum`, `network`, `routing`, `entanglement`, `fidelity`, `memory`, or `optimization`). Rank deterministically by the number of selected papers carrying the keyword, then mean provider score, then lexical order. Select at most four terms representing at least two papers; fail before search if this is impossible.

Compile one `entanglement AND (term1 OR …)` OpenAlex title-and-abstract query, freeze the plan and hashes, and run one round of at most two pages of 100 results (**two logical requests, 200 returned slots maximum**). Save raw calls, metadata provenance, returned and exact-identity counts, and incremental identities relative to C. The known question and papers informed the design; their rediscovery is descriptive. No recursive learning, PDF, citation traversal, human screening, or product-default change occurs. Use no live DEIXIS library or port `8765`, and store no credentials.
