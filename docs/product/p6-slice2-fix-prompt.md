## Decisions taken (the plan's own defaults; do not reopen)

- **Fix 1: refuse the restore.** In `restore_column`, when the restored column has a `lineage_role`, after the UPDATE and inside the same transaction, compute the stale set as it would be after the restore (use `stale_link_revisions` from `lineage/run.py`; import it inside the function if a top-level import is circular) and test whether the active, non-stale, non-independent_parallel, live-endpoint graph contains a directed cycle. If it does, raise `InvalidTableInput` with a message that names the cause (restoring this column would re-activate a development link that closes a cycle with another active link; remove or edit that link first); the transaction rolls back, the column stays removed, no event is written. Add a small whole-graph cycle test to `LineageStore` (for example `has_cycle(table_id, stale_revisions)`) that reuses the same edge filter as `_cycle` so the two cannot drift; do not copy the filter. Columns without a lineage role skip the check. A restore that creates no cycle behaves exactly as today. Do not rewrite or stale any revision. Both `run` and `LineageStore` imports inside `restore_column` stay function-local (module-level imports would make cycles). The guarantee is limited to column restore: other ways to re-activate an old link (for example re-including an excluded row after a cycle was closed around it: A->B->C, C->A added while B is excluded, B re-included) are a known open limit; do not touch them, only note them in your final message. If `restore_column` is called inside an outer transaction whose caller swallows the error, the rollback is the caller's business; say so in a code comment only if it fits in one line.
- **Fix 2: one shared condition.** Define the `what_changed` condition once exactly `isinstance(value, str) and bool(value.strip()) and 1 <= len(value) <= MAX_WHAT_CHANGED`, the length measured on the raw text, not on `strip()` in one place both modules use (the domain side is the natural home, since `store.py` already depends on the domain and `contracts.py` must not import the workflow package; put the constant and a tiny predicate where both can import them without adding any new workflow/lineage dependency to `contracts.py` (existing ones are not your job), keep `MAX_WHAT_CHANGED = 500` unchanged and exported where it is imported today).
