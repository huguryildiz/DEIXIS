# PRISMA-S-grounded hybrid discovery — proposed design

**Status:** proposal for an isolated, opt-in evaluation. No product behavior, default search strategy, or PRISMA claim changes. **Date:** 2026-09-18.

## Decision boundary

PRISMA-S is a **search-reporting checklist**, not a search algorithm or a certification of a systematic review. This design makes a bounded text-search → citation-search → term-feedback workflow auditable against its 16 items. A DEIXIS research project can export a complete or explicitly incomplete *search-method record*. A PRISMA 2020 systematic-review flow diagram is available only when the review has recorded eligibility criteria, record screening, report retrieval and full-text eligibility decisions at the appropriate levels. A source-linked answer or a model screening proposal alone does not meet that gate.

In the PRISMA 2020 diagram for databases and other methods, initial and term-feedback database searches feed the database side; backward and forward citation searching feed the other-methods side. Preserve per-route counts and cross-route duplicate identities in an accompanying ledger. The diagram's two branches join at **studies included**; its other-methods branch has no title/abstract screening or deduplication box. If citation-derived records receive preliminary title/abstract screening, record those decisions in an accompanying table, then count only reports actually sought in that branch's `reports sought` box. Never make an unassessed record disappear to make the diagram balance. The 2026-09-18 quantum pilot cannot fill the screening, retrieval, eligibility, or inclusion boxes: it did not perform those review decisions.

This proposal adds a candidate-discovery experiment; it does not claim exhaustive recall, semantic citation support, or validated mathematical-model comparison. It does not supersede [D11](../decisions.md), [D60](../decisions.md), [D64](../decisions.md), [D66](../decisions.md), or [D67](../decisions.md). The separate [query-structure proposal](search-query-structure-design-2026-09-18.md) is not implemented or silently adopted here. Its recorded rule/table contradictions must be resolved before it can be selected as a query arm.

## What the researcher sees

1. **Freeze the question and method.** Record the question, interpretation, eligibility criteria for *this evaluation*, included providers, selected model/effort, Gemini embedding model, exact query compiler, per-stage request/result/screening budgets, seed and round caps, search dates, and stop rules. The query plan is frozen before live requests. Any later term-derived query is a new, linked iteration, never an edit to the original query.
2. **Run initial text searches.** The existing `SearchPlan` proposes concepts and providers; application code compiles provider-valid strings. Store the exact sent query, field, filters, page/offset, requested limit, response status, returned count, provider-reported total, and delivery class. A 429, 400, timeout, or entitlement failure is incomplete delivery, not zero results. Never substitute another provider silently.
3. **Resolve identity, then propose seeds.** Preserve provider records and version identities. Gemini `gemini-embedding-2` embeds the question and available title/abstract text; code computes question similarity and diversity. A minimum question-relevance rule comes **before** diversity; its numerical threshold, text-depth rule, tie-breaks and zero-seed outcome are frozen in the run protocol. At most three seeds are proposed with scores, record text, and reasons; the user confirms them in the product. A title-only vector, if allowed by the protocol, is explicitly `title_only`; a missing abstract never becomes invented text. Store model identity, vector dimension and vectors or their lossless private snapshot. Gemini is a remote embedding provider: the selected text leaves the local machine, and that route is recorded. A Gemini failure blocks this arm; it does not silently switch to OpenAI or another model.
4. **One citation round.** For each confirmed seed, fetch bounded backward references and forward citations from the preselected indexes. Save every attempted edge with seed, direction, provider, page/offset, round, and status. OpenAlex `referenced_works` is a complete identifier list attached to the returned seed record, not a paged edge endpoint: preserve all IDs, then hydrate only the frozen number in a deterministic order. Mark the rest `not_hydrated`. Crossref DOI-only references likewise require hydration before title/abstract screening or term extraction; DOI-less references may remain `unresolvable_reference`. Paginate actual paged endpoints only within the frozen per-seed and global budgets; record truncation and provider totals separately from returned rows, with `provider_total=unavailable` where an endpoint supplies none.
5. **Merge and screen.** Deduplicate provider records conservatively into work/version groups without erasing provider provenance. The existing model screening role may propose `include`, `exclude`, or `uncertain` with its actual reading depth. A model `exclude` cannot be the only reason to make a record disappear from the candidate ledger or prevent a user's inclusion. For the evaluation, human labels are the reference; title/abstract decisions and full-text decisions are distinct.
6. **Prefetch bounded PDFs while discovery continues.** After identity resolution, freeze a ranked and route-diverse list of at most 20 provisional works for an isolated trial; the cap and ordering are set without using control DOIs or the Elicit inclusion list. A separate queue looks for open PDFs of those works while later search requests run. Reuse the DOI/version-gated OpenAlex, Unpaywall, Crossref and CORE lookups, with the existing exact-title web-search route if those fail and its configured key is available; record each branch and its separate budget. Reuse the bounded public-URL fetcher. A provider PDF URL is only a candidate until a real PDF is fetched; an uncertain or different version waits for identity assessment and cannot silently supply the published record's text. Record candidate, attempt, PDF-byte hash, provider-stated version and identity basis, extraction status, and page count separately. Matching DOI/version metadata and valid PDF bytes do not by themselves establish the document's content identity; this remains unchecked until inspected. Run the existing bounded PyMuPDF text-layer extraction immediately on a validated PDF download, preserving physical pages and `partial`/`no_text`/failure states. Scans need the existing explicit OCR path. Marker reads selected mathematical and table pages in a separate lower-priority queue; discovery and preliminary screening do not wait for it. A feature assertion involving an equation cannot be called equation-verified while this queue is pending or failed. Neither a downloaded PDF nor all extracted pages count as *assessed full text* until someone actually inspects the relevant passages. For the trial, an isolated [PDF-prefetch runner](../../scripts/isolated_pdf_prefetch.py) provides this stage without changing the live library or the frozen 2026-09-18 result.
7. **Learn terms from confirmed positives.** Only works whose relevance was confirmed by the user or evaluation raters enter the positive set. Compute document frequency for words and technical phrases in available title/abstract text, compared with a recorded background set from the same search domain. Keep the positive/background counts and the exact source records for every term. The LLM may group candidates into question concepts and flag ambiguity; it cannot invent an unattested term or directly send a query. The user approves a bounded term set. DOI-only and unverified model-positive records contribute no term evidence. A separately preregistered full-text term arm may be compared, but must not leak its terms into the title/abstract-only comparator.
8. **Run one term-feedback text round.** Code turns approved terms into provider-valid queries under a separately reserved request/result budget. Record each query's parent terms, source records, human approval, compiler version, and exact sent string. Every work keeps **all** timestamped discovery routes; report first-route and any-route counts separately. A term-feedback hit found earlier via citation remains a hit in both routes.
9. **Conditional second citation round.** Select at most two newly human-confirmed relevant works from the **first citation round**, subject to the frozen relevance/diversity rule. Open one more bounded backward/forward round only if at least one newly relevant work was confirmed after reviewing at most the protocol's first-round screening cap, and at least four edge-list requests remain per chosen seed. These numbers and the chosen seed count are frozen before requests; no post-outcome relaxation. No third round and no automatic product expansion from merely model-positive or uncertain works. Record the reason when the second round is skipped or stopped. An explicitly labelled isolated *machine-provisional* experiment may auto-select seeds and terms without claiming human confirmation or validating this product gate.
10. **Report and hand off evidence.** Present counts by text round, citation direction/index/round, and term-feedback round. Then report unique records, work groups, records screened, PDFs sought/downloaded/readable, reports actually assessed, full-text exclusions with reasons, and included studies only to the extent actually determined. Found, screened, included, downloaded, extracted, inspected, supplied to the answer model, and cited are separate stages. A later answer reads only user-included sources and retains its existing passage-anchor contract.

## Finite budget and failure contract

The evaluation protocol fixes numbers *before* any provider request. A sample profile, to be measured rather than adopted as the product default, is: at most three initial seeds, two citation indexes, two directions, one page per seed/direction/index, and at most two new seeds in round two. This yields at most **20 planned edge-list requests** (`3 × 2 × 2 + 2 × 2 × 2`), plus separately capped text, hydration, and retry requests. `25` is a per-request result ceiling in that example, **not** a global candidate or screening ceiling. The PDF arm separately freezes at most 20 candidate works, up to five location lookups (OpenAlex, Unpaywall, Crossref, CORE and exact-title web search) and two download attempts per work, at most two in-flight PDF jobs, the existing 30 MiB PDF-byte cap, and one Marker reader; its lookup and fetch calls do not vanish from the request budget. Preflight must show how all returned slots fit the candidate/screening allocation or state which records will remain uninspected and why. The live 8765 library is never an evaluation target.

The 2026-09-18 development run took only the first 50/25/25 OpenAlex rows from three queries, despite provider totals of 2,944/209/279. These limits make it a shallow diagnostic, not a comprehensive search. A new run should predeclare more text-result slots, actual next-page requests, and a question-derived synonym plan; it should compare additional pages and new query variants at the same request, returned-record and screening budgets. Track marginal unique and human-relevant yield per page, term, and route before choosing a stopping rule. Terms learned from this quantum case or the Elicit misses are development-informed and cannot be presented as independent holdout gains.

Each request has one final state: `completed` (including `returned_count=0`), `rate_limited`, `invalid_request` (such as HTTP 400), `unauthorized` (401/403 or entitlement failure), `timeout`, `parse_error`, `server_error`, or `not_sent`. Attempts have separate `planned` and `sent` timestamps and HTTP status. Delivery class is derived from the state, not manually assigned. A retry consumes its own request allowance. D67's process-wide Semantic Scholar gate is reused; it does not coordinate other processes using the same key or guarantee a 200. Record keyed versus anonymous access without recording keys. Provider-specific pagination uses OpenAlex `page`/cursor and Semantic Scholar `offset`/`limit`, under the frozen caps. An HTTP 400 triggers parameter diagnosis in a **separate** follow-up record; it never rewrites the frozen run. A provider branch that never delivered remains unavailable in counts and comparisons.

## Data and count contract

Store immutable, linked entries for: `search_iteration` (initial, term-feedback); `search_request` and attempts; `provider_record`; `citation_edge`; `record_identity` and version evidence; timestamped `discovery_route`; `seed_proposal` and user decision; `term_candidate` with frequencies, background-set definition and source IDs; `query_proposal` and approval; `screening_batch` with exact model input/hash; model screening proposal; human record-screening decision and rater/blinding provenance; PDF lookup/candidate/fetch attempt; PDF identity and version assessment; byte hash and page extraction; Marker queue state; report-retrieval attempt; full-text eligibility decision; `budget_ledger`; and `export_snapshot` with code, protocol, query, model, method/prompt and data hashes. These are proposed product records, not existing tables. Secrets and private payloads stay in configured application data, outside Git; exports omit credentials and allow private metadata to be withheld while marking the omission.

Count invariants:

- `provider_total` is a provider claim about its index, not returned, unique, screened, or included records.
- Returned rows, unique provider records, merged work/version groups, and included studies have different denominators. A DOI set is not a lossless duplicate resolver; DOI-less records and preprint/publisher versions remain traceable.
- Citation *edges* are not paper counts. Count backward and forward edges separately, and expose overlaps between text and graph routes without attributing the same work twice to the union.
- PDF candidates, successful downloads, readable text layers, Marker-processed pages and actually assessed reports are distinct. A PDF lookup failure is not evidence of no full text; a PDF of uncertain version is not silently assigned to a published record. An open-PDF queue may bias which candidates receive deeper assessment, so preserve unassessed and paywalled statuses independently of relevance.
- Only actually viewed title/abstract records count as title/abstract screened; only retrieved and read reports count as full-text assessed. LLM proposal, missing abstract, and failed PDF retrieval have their own states.
- Model-ranked or model-excluded records left unseen remain `unassessed`; they cannot be silently counted as human-screened or as automatically removed. If a future workflow deliberately removes them before screening, record the exact automation rule and count them in PRISMA 2020's automation box. If unassessed records remain, the diagram is incomplete.
- A PRISMA-style flow snapshot must reconcile every transition or display `incomplete` with the unreconciled records and cause. It cannot fill missing boxes with inferred zeroes.

## PRISMA-S 16-item export map

The export contains an item-by-item manifest with `reported`, `not_applicable` plus reason, or `incomplete` plus missing evidence. The wording below is a DEIXIS mapping, not a replacement for the official checklist.

| Item | DEIXIS export evidence |
|---|---|
| 1. Databases | Exact database/platform and provider identity for every text and graph request. |
| 2. Multi-database searching | State whether one interface searched several databases; normally `not_applicable` for the current direct connectors. |
| 3. Study registries | Explicitly list registry searches, or `not_applicable` with scope reason; do not imply that scholarly indexes cover registries. |
| 4. Online resources/browsing | Any separately authorized browsing route, exact resource, date and method, or `not_applicable`. |
| 5. Citation searching | Seed identities, forward/backward direction, index, round, limits, statuses and counts. |
| 6. Contacts | Contacts attempted and method, or `not_applicable`; never infer contacts from metadata. |
| 7. Other methods | User-uploaded seeds and other non-database routes, each labelled; term-feedback database searches belong under items 1, 8 and 13. |
| 8. Full search strategies | Verbatim sent queries, syntax/field, source, initial/term-feedback iteration, pagination and request descriptions. |
| 9. Limits/restrictions | Date, language, type, page depth, candidate and round caps, including rationale. |
| 10. Search filters | Named validated filters if used; otherwise `not_applicable`. Ordinary model ranking is not a validated search filter. |
| 11. Prior work | Any reused query or seed from an earlier review, with source; otherwise `not_applicable`. |
| 12. Updates | Distinguish later reruns/updates from the planned within-run term-feedback iteration. |
| 13. Dates | Per-request search dates and snapshot date, not only the report date. |
| 14. Peer review | Search-strategy review by a qualified person if performed, with date and changes; otherwise explicitly report that none was performed. A reviewer-model verdict is not human peer review. |
| 15. Total records | Per-source returned counts and the reconciled union; provider totals appear in a separate column. |
| 16. Deduplication | Identity keys, version grouping, ambiguous pairs, counts before/after and algorithm/version. |

TARCiS adds explicit citation-search reporting: why those seeds, all directions and indexes, round dates, number of rounds, deduplication and screening method, and why expansion stopped. PRISMA 2020's flow diagram adds report retrieval and eligibility stages that PRISMA-S alone cannot create.

## Evaluation before a default change

Use unseen questions and freeze eligibility criteria, models/effort, provider set, attempted and delivered request budgets, result slots and human screening budget. Compare at least: (A) current text-only strategy, (B) the same total budget spent on **predeclared additional text queries or next pages**, and (C) text + one citation round + term-feedback, with the conditional second round separately attributed. Arm B's exact queries, page order and stop rule are fixed before any response from A or C. To measure early PDFs, give compared arms the same PDF candidate/lookup/download budget, or run a separate factorial PDF arm; do not credit extra full-text access to graph depth. Measure time to first readable page, version-confirmed PDF coverage, page extraction failures, feature assertions with inspected passage support, Marker latency and equation errors on a hand-checked sample. The known six quantum DOIs and Elicit included CSV are development diagnostics, not a holdout or field-recall denominator. Human assessors judge relevance blind to discovery route where the available metadata permits; report rater time separately from machine time, unique relevant works, relevant works per request and per record screened, route overlap, missing-metadata share, failure share and elapsed time. On a small question set results remain descriptive. Evaluate seed selection and LLM term proposals separately from graph depth. No arm inherits a successful response from another arm without recording the shared cache and its effect on comparability.

The current application has text discovery and a `SearchPlan` v2 compiler but no citation-expansion workflow. Its Gemini embedding path ranks sources/passages; it does not select graph seeds. Implementing this proposal requires new versioned step/record contracts, persistence and migrations, provider graph adapters, budget enforcement, export reconciliation and proportionate tests. It is not a prompt-only change. No existing decision is promoted to a default by this document.

## Reuse boundary and delivery sequence

The [PRISMA2020 R package](https://github.com/prisma-flowdiagram/PRISMA2020) can render a flow diagram from counts; the [official PRISMA page](https://www.prisma-statement.org/prisma-2020-flow-diagram) links its Shiny application. Independent Python renderers such as [prismaflow](https://github.com/osl-incubator/prismaflow) are possible export targets. [citationchaser](https://github.com/nealhaddaway/citationchaser) is a citation-search implementation, not a substitute for DEIXIS's identity, access, and provenance contracts. None of these packages decides relevance or supplies missing screening and full-text decisions. A native renderer or package dependency is a later implementation choice after a count-schema export has been validated. Package claims and maintenance, license, input semantics, and output accessibility require review before adoption.

Deliver in four separable slices: (1) immutable text-request/hit ledger and reconciled counts; (2) bounded citation edges and identity/hydration; (3) user-confirmed seeds/terms, one feedback query, and conditional second round; (4) PRISMA-S manifest plus optional PRISMA 2020 flow export only when the review-level gate is satisfied. Each slice can report incomplete evidence without drawing a completed review diagram. The existing answer pipeline remains a downstream consumer of user-included records; its passage citation checks do not certify the search.

## Frozen quantum development case and answer gate

For an isolated trial, use the exact question: “Which mathematical optimization models have been proposed for end-to-end entanglement distribution in quantum networks? Compare their decision variables, objectives, constraints, and treatment of routing, scheduling, memory capacity, fidelity, and decoherence. For each model feature, cite the supporting paper and state whether it was verified from the abstract or full text.” This question, six previously known DOI controls, prior graph pilot, and Elicit export are **development material**. Freeze requests, seeds/selection rule, result caps, retry caps, term rule, and stopping decision before new provider responses. A trial can reuse the earlier frozen pilot as a historical comparator, but a new result must have its own request ledger and cannot retroactively repair that pilot.

Before reading, freeze the feature columns: decision variables, objective, constraints, routing, scheduling, memory capacity, fidelity, and decoherence. For every proposed model feature, the answer ledger must hold a source/version identity, exact feature assertion, supporting passage or abstract span, reading depth, locator if full text, and one of `supported`, `contradicted`, `not_found_at_depth`, or `uncertain`. “Not stated in the abstract” is `not_found_at_depth`, not absent from the paper. Full-text verification requires a retrieved, identifiable document and inspected passage; a DOI landing page, model summary, or Elicit row is insufficient. If only abstracts can be inspected, publish an abstract-limited comparison with unknown cells rather than filling equations, variables, or constraints from titles or generic domain knowledge.

Compare the trial with the saved Elicit audit on two distinct axes: exact DOI and defensible version-group overlap with its **nine included papers**, and qualitative differences between feature assertions at matched reading depth. Mark a known-control DOI or Elicit-included work used as a seed separately from a genuinely new graph recovery; controls found as seeds never count as marginal graph gains. A DOI-less Elicit row requires an explicit, auditable identity assessment before a version-group match. The two efforts may have different eligibility criteria, dates, access and search budgets; if Elicit's nine works are not re-screened under this protocol by human raters, overlap is a descriptive diagnostic only. The Elicit export exposes an inclusion list and query history, not its complete candidate pool or provider-internal retrieval. Neither `trial candidates / Elicit included` nor overlap with the six known DOIs is a recall estimate or equal-budget winner. Report every unavailable provider branch, missing PDF, unreviewed record, and undecided feature explicitly. No human-labelled relevance or completed PRISMA 2020 selection flow is claimed until those actions actually occur.
