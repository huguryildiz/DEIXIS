# Compact vocabulary: separate development probe

**Status:** frozen before the new OpenAlex queries below. The six LitSearch questions in `scripts/search_method_cases_2026-09-17.json` have already been scored in the earlier external-question comparison and are now a **development set**, not a holdout.

The preceding run found only two of 17 gold works across its best arms, although DOI lookups found all 17 works in OpenAlex. The original model often proposed long, narrow core phrases: for example `contrastive learning augmentation effects` and `dependency-based relation extraction`. This probe changes only vocabulary construction. One `gpt-5.6-luna` medium call per question, seeing the question but no gold works or previous search responses, proposes one or two canonical core phrases and one to three facet phrases. Every phrase must contain at most three words. The existing OpenAlex compiler writes both queries: core-only (first 100) and core AND facet (next 25). No hidden repair or extra provider call is allowed. Missing, invalid, wrong-model, or failed outputs remain failures.

The primary measure is exact-DOI coverage of the 17 frozen LitSearch gold works, by question and after each query. Secondary measures are returned and distinct works, retries, model tokens, and latency. A model reviewer may blind-label the top ten results of the second request from title and abstract; those labels remain provisional. A promising development candidate must find at least one gold work in four of six questions and gain gold works in at least two questions from the second request. Even if it passes, it requires a new independent case set before a product change. This run uses only OpenAlex in an ignored `.local/search-compact-development-2026-09-17/` directory and does not touch the live library or port 8765.
